# restic-docker-backup Web 版 PRD

> 版本：v1.1（基于《Web版改造方案》v2.3.4）
> 前置文档：《Web版改造方案 v2.3.4》（架构、API、鉴权、分阶段计划以该文档为准，本 PRD 不重复论证技术决策）
> 前端基线：Vite + Vue 3.5（组件库选型见 §7，已裁决 Naive UI）

---

## 1. 产品概述

### 1.1 一句话定位

把 restic 备份工具从命令行改造为**单容器 Web 应用**：自托管运维者通过浏览器完成仓库配置、备份源选择、定时策略、快照浏览与恢复，无需编写任何脚本或 YAML。

### 1.2 目标用户与画像

| 用户画像 | 特征 | 核心诉求 |
|---|---|---|
| 自托管个人玩家 | 家用服务器/NAS，跑 Docker，有 Duplicati/Veeam 等图形备份工具使用经验 | 界面操作、防误删、恢复不踩坑 |
| 小团队运维者 | 管理几台 VPS/物理机，维护 Web 服务与数据库 | 定时任务可靠、失败可见、能审计谁做了什么 |
| 安全敏感的自托管者 | 暴露公网或共享宿主机 | 默认安全（鉴权、最小权限、危险操作有确认门） |

共同点：熟悉 Docker 基础操作（能改 compose 并 `docker compose up`），但**不愿维护 bash 备份脚本**。

### 1.3 核心价值主张

1. **零脚本运维**：日常调整（仓库、凭据、策略、调度、通知、dump）100% 在 Web 界面完成，不碰 compose、不重启容器；
2. **全盘可备、增删零重启**：`/` 整盘挂载为 `/host`，备份源在界面任意勾选，加源不需要改挂载；
3. **恢复不踩坑**：P1 仅提供"恢复到时间戳子目录"这一默认路径，从产品层面杜绝误覆盖（P2 才开放覆盖确认流）；
4. **安全默认**：鉴权是 P1 第 0 项，无鉴权不上其他功能；危险操作三重确认 + append-only 审计。

## 2. 产品目标与成功指标

| # | 目标 | 成功指标（可衡量） |
|---|---|---|
| G1 | 快速上手：全新宿主机极简部署 | P1 DoD：全新宿主机 **30 分钟内**完成部署（含 bind-mount 属主处理）+ 配置仓库 + 首次备份 + 从快照恢复一份文件到时间戳子目录，全程有鉴权保护，首启改密流程完整走通 |
| G2 | 备份可靠 | 常规路径下备份任务成功率 ≥ 99%；调度任务漏跑补跑正确率 100%（P2 DoD）；容器重启后任务状态与仓库锁恢复正确 |
| G3 | 误操作零事故 | 生产环境中不发生任何"未经确认门的覆盖/裁剪"事故：P1 阶段不存在任何直接覆盖路径；P2 覆盖预览清单与实际覆盖文件 100% 一致（P2 DoD） |
| G4 | 失败可见 | 任务失败/非 root 静默跳过均可通过界面或通知在任务结束后即时感知（skipped 计数展示 + 阈值告警） |

## 3. 用户故事（角色：管理员）

### 旅程 A：首次部署引导

**US-A1 首启改密**
> 作为管理员，首次打开 Web 界面时，我希望系统生成随机管理密码并一次性展示、强制我修改，这样默认凭据不会泄露到 docker logs 或长期沿用。

- AC1：首次启动生成的随机密码**仅在首启页面一次性展示**，不打印进 docker logs；
- AC2：未完成改密前，除首启引导页外所有页面/API 均不可访问；
- AC3：新密码哈希以 argon2id（不支持时 bcrypt）存储，明文不落库、不落日志。

**US-A2 登录与防爆破**
> 作为管理员，我希望登录有暴力破解防护，这样暴露公网时账号不被穷举。

- AC1：同一账号连续失败 5 次锁定 5 分钟，锁定时长指数退避（每次翻倍，上限 1 小时）；
- AC2：登录接口独立限流；会话 24h 有效、活跃滑动续期，登出即销毁；
- AC3：写请求校验 Origin/Referer 同源（CSRF 防护）。

### 旅程 B：仓库配置

**US-B1 配置仓库与凭据**
> 作为管理员，我希望在界面上选择仓库类型（s3/b2/本地）并配置地址、后端凭据、host 标识，这样无需编辑 env 文件即可接入对象存储。

- AC1：仓库类型表单按类型联动（P1 仅 s3/b2/本地三种，sftp/rclone 不出现）；
- AC2：凭据字段保存后 API 只回脱敏状态（has_value）与"来源"标识（UI 设置 / 环境变量覆盖）；
- AC3：compose 环境变量已设置的凭据，对应输入框置灰并标注来源；
- AC4：仓库密码不出现于任何表单/API——仅提示"密码文件挂载状态：已配置/缺失"。

**US-B2 首次备份前 dry-run 确认**
> 作为管理员，我希望首次正式备份前看到预计扫描范围（含内置排除集生效结果）并确认，这样不会把 proc/docker 目录之类无意义内容写进仓库。

- AC1：首备前以 `restic backup --dry-run` 展示扫描范围，用户确认后才执行；
- AC2：内置排除集（语义核心集 proc、sys、dev、run、var/run、var/lib/docker、tmp、lost+found，按挂载模式派生前缀，方案 §3.1 v2.3.2）强制生效、不可删减，界面可见；
- AC3：dry-run 扫描范围中出现 proc/sys/dev/run/docker/lost+found 类目录名时 UI 黄色警告（不强制拦截，方案 §3.2 四层防线）。

### 旅程 C：备份源选择

**US-C1 浏览与勾选备份源**
> 作为管理员，我希望在 `/host` 下自由浏览并勾选目录作为备份源，全程看到的是宿主机原路径（如 `/etc/nginx`），这样增删源不用改 compose、不用重启。

- AC1：源选择、快照浏览、恢复目标三处 UI 均展示剥掉 `/host` 前缀的原路径；
- AC2：增删源即时生效，无需重启容器；
- AC3：所有路径输入规范化并校验在允许前缀内。

### 旅程 D：手动/定时备份

**US-D1 手动备份与实时进度**
> 作为管理员，我希望点击"立即备份"后看到实时进度（百分比、已传字节、文件数），刷新页面进度不丢，这样长任务期间可以放心离开再回来。

- AC1：进度经 SSE 推送，事件含递增 id；页面刷新凭 job_id 重订阅，先回放日志尾部再续流（Last-Event-ID 断点续传）；
- AC2：同一仓库已有任务 running/pending 时，手动触发返回 409 并明确提示"已有任务进行中"，不做静默排队；
- AC3：运行中任务可取消（SIGTERM → 宽限期 → SIGKILL），终态记为 cancelled 并可见。

**US-D2 定时策略（P2 开放多策略 UI）**
> 作为管理员，我希望为备份配置 cron 表达式、jitter、重试与保留档位，漏跑的任务在恢复后自动补跑，这样容器重启/宕机不丢备份。

- AC1：调度统一为 cron 触发器（策略级 cron + 全局缺省）；改动由调度器动态重载、改完即生效无需重启；
- AC2：启动时扫描 last_run，当天已过点未成功的任务立即补跑；
- AC3：P1 仅暴露一条默认策略（数据模型按多策略建表），P2 开放多策略 UI。

### 旅程 E：快照浏览

**US-E1 快照列表与文件树**
> 作为管理员，我希望分页浏览快照列表并懒加载展开快照内文件树，历史再长、目录再大也不卡。

- AC1：snapshots 与文件树 API 分页（或流式转发），前端虚拟滚动渲染；
- AC2：文件树子目录懒加载；路径语义为宿主机原路径。

### 旅程 F：恢复

**US-F1 恢复到时间戳子目录（P1 唯一恢复路径）**
> 作为管理员，我希望恢复时目标自动为新建的时间戳子目录（如 `/restore/etc-20261010-0138/`），这样绝不覆盖现有文件。

- AC1：P1 恢复向导仅提供"恢复到时间戳子目录"，不存在任何覆盖选项；
- AC2：恢复进度经 SSE 实时推送，完成后展示结果路径与文件数；
- AC3：恢复结果目录路径语义为宿主机原路径结构。

**US-F2 原位恢复（P2，受能力与确认门双重限制）**
> 作为管理员（ro 档/安全部署），我希望原位恢复选项在不可用时明确置灰并解释原因，而不是隐藏；可用时（rw 档 + root）经过覆盖清单确认后才执行。

- AC1：`/host` 为 ro 档时原位恢复置灰并提示"请将挂载切为 rw"；
- AC2：rw 档下原位恢复必须先展示"将被覆盖文件清单"（快照 ls × 目标磁盘现状自研比对）→ 输入确认文本 → 二次确认 + "停止相关服务"提示，全部入审计日志；
- AC3：非 root 档下 root 属主文件恢复部分失败的文件在任务日志中列明。

### 旅程 G：运维

**US-G1 通知（P2）**
> 作为管理员，我希望配置 healthchecks ping、飞书/钉钉 webhook 或 MeoW 推送（手机 App），任务失败和 skipped 超阈值时收到通知；可按渠道开启脱敏（敏感内容不出站），并提供"发送测试消息"验证配置。

- AC1：通知事件覆盖 /start、/fail、成功摘要；skipped 计数超阈值（可配）触发告警通知；
- AC2：提供测试按钮，发送结果即时反馈；
- AC3：MeoW 渠道可用——按昵称推送，成功以响应 JSON `status` 字段判定（HTTP 恒 200），429 限频时记录失败且不重试推送；
- AC4：渠道级脱敏开关——勾选后敏感变量（路径/错误详情/仓库/主机名/数据库名）从消息中**直接剔除、不显示占位字样**，仅保留任务号/类型/状态/时长/字节数等摘要并附任务详情深链；第三方渠道（MeoW）默认勾选，自建 webhook 默认不勾。

**US-G2 非 root 档能力提示**
> 作为以非 root 运行的管理员，我希望首次备份后明确看到 skipped 文件计数与提示，这样不会误以为备份是全量的。

- AC1：任务日志记录 skipped 文件计数与明细，任务完成后 UI 展示 skipped 数量；
- AC2：skipped > 0 时展示"非 root 档存在不可读文件，如需全量备份请切 root 档"提示；
- AC3：界面提供"运行用户 × 挂载模式能力四象限"说明，当前组合高亮。

**US-G3 运维维护（P2）**
> 作为管理员，我希望在界面查看 restic 缓存占用并一键清空、查看 append-only 审计日志与任务历史，这样日常维护不出终端。

- AC1：清缓存操作明确提示"不丢数据，仅下次备份变慢"，入审计；
- AC2：审计日志只可查询，不存在任何更新/删除入口；
- AC3：任务历史含起止时间、退出码、摘要、字节数与日志文件链接；按保留天数（默认 90 天）自动清理，单任务日志按大小截断保留尾部。

## 5. UI / 页面结构设计（文字版线框）

导航结构（登录后）：左侧主导航 = 仪表盘 / 备份源 / 策略与调度 / 任务历史 / 快照浏览 / 系统设置（仓库与凭据、通知、维护、审计）/ 运行状态角标。

| # | 页面 | 核心元素与交互 |
|---|---|---|
| 1 | **登录页** | 密码输入 + 登录按钮；失败提示不区分"密码错误/已锁定"细节之外的安全文案；锁定时显示剩余锁定时长；无注册入口（单管理员） |
| 2 | **首启引导页** | 一次性展示随机管理密码（带复制按钮 + "关闭后无法再查看"强提示）→ 强制设置新密码（强度校验）→ 完成后跳转仪表盘；未完成改密前全站不可达 |
| 3 | **仪表盘** | 仓库状态卡（连接/锁状态/仓库容量）、最近任务列表（状态/耗时/字节数）、下次调度时间、四象限能力提示卡（当前"运行用户×挂载模式"组合高亮，其余组合置灰说明能力边界）；skipped/失败等异常状态以醒目色块提示 |
| 4 | **仓库配置页** | 仓库类型单选（s3/b2/本地，类型联动表单）、地址、后端凭据（脱敏回显 has_value、来源标识、env 覆盖时置灰）、host 标识、密码文件挂载状态提示（只读，无输入框）、"测试连接"动作 |
| 5 | **备份源页** | 源目录树浏览器（`/host` 或 `/sources` 按模式，虚拟滚动）、勾选/取消源列表（原路径语义展示）、内置排除集只读展示（按模式派生，标注"强制生效"）、追加排除规则输入、首次配置后"预览扫描范围（dry-run）→ 确认"门禁；dry-run 中出现伪文件系统/docker 类目录名时黄色警告 |
| 6 | **策略与调度页**（P1 单默认策略，P2 多策略） | 策略表单：cron 表达式（含常用模板快捷填充与下次触发时间预览）、jitter、重试、保留档位（keep_last/hourly/daily/weekly/monthly/yearly）、group_by、one-file-system、压缩开关、限速（上传/下载 KiB/s，P2）；保存即时生效提示；**forget 操作必须先出 dry-run 预览 → 确认 → 执行** |
| 7 | **任务历史页** | 任务列表（类型/状态/起止/退出码/字节/摘要），状态色区分（success/failed/interrupted/cancelled）、日志详情抽屉（skipped 文件计数与明细折叠展示）、失败任务"重试"按钮、进行中任务"取消"按钮（二次确认） |
| 8 | **快照浏览页** | 快照列表（分页/虚拟滚动：时间/host/tag/大小）、快照文件树（懒加载子目录、原路径语义）、"从此快照恢复"入口直达恢复向导 |
| 9 | **恢复向导页** | 单页表单：① 恢复到哪里（P1：仅"自动时间戳子目录"；P2 增加"原位置"，ro 档**置灰 + 原因提示**，rw 档选中后进入覆盖清单确认流：被覆盖文件列表 → 输入确认文本 → 二次确认 + "停止相关服务"提示）；② 恢复进度区（SSE 实时进度，刷新可续）；③ 完成结果区（目标路径、文件数） |
| 10 | **通知设置页**（P2） | healthchecks URL、webhook 地址与模板编辑、MeoW 渠道（昵称）、各渠道脱敏开关（勾选后敏感变量从消息中直接剔除不出占位符，说明文案"敏感内容不出站，可在任务详情查看"；默认：MeoW 勾选 / 自建 webhook 不勾）、成功是否通知开关、skipped 告警阈值（默认 100，0=任何 skipped 即告警）、"发送测试消息"按钮（即时反馈结果） |
| 11 | **系统设置页**（P2 为主） | 分区：DB dump 配置（类型/主机/端口/账号/密码/库名/保留天数；pg 版本不匹配时显式报错提示"镜像内 client 为 N、server 为 M：请以 Alpine edge 源自构建镜像，或等待镜像更新收录"）、行为开关（AUTO_INIT/AUTO_UNLOCK/CHECK 抽样比例/月度全量日）、时区、缓存维护（占用查看 + 一键清空，确认弹窗注明"不丢数据，仅变慢"）、管理员改密 |
| 12 | **审计日志页**（P2） | append-only 日志查询（时间/操作/对象/结果），**无任何删除或编辑入口**（UI 与 API 一致），仅支持整段归档滚动的说明文案 |

**贯穿性安全交互规范**：
- **危险操作三重确认**（forget --prune / unlock / 原位恢复）：预览结果展示 → 输入指定确认文本 → 二次确认弹窗，全程入审计；
- **SSE 实时进度**：所有长任务（backup/restore/check/forget）统一进度组件，含 Last-Event-ID 断点续传与 15s 心跳保活；
- **非 root skipped 文件展示**：任何备份任务完成页若 skipped > 0，展示计数 + 明细 + 切档建议，不得静默。

## 6. 非功能需求

| 类别 | 需求 |
|---|---|
| **安全** | ① 全部 API（含 SSE）走 cookie session 鉴权，SSE 禁用 query token；② 仓库密码永不入库、永不出 API；后端凭据 API 脱敏（仅 has_value + 来源）；③ restic 参数经固定白名单拼装，无自由命令透传；路径规范化 + 前缀校验；④ 危险操作三重确认 + append-only 审计（无更新/删除 API）；⑤ 登录防爆破（指数退避）+ 登录接口独立限流；⑥ `/data` 目录 chmod 700 且部署文档要求排除出宿主机其他备份工具范围；⑦ HTTPS 双轨（Q2 已裁决）：首选反代（部署文档含 Caddy 自动 HTTPS 示例），镜像内置"挂证书"式 TLS 选项（UI 配证书/私钥路径，无自动签发续期） |
| **性能** | ① snapshots/文件树 API 分页（limit/offset 或游标）或流式转发，前端虚拟滚动，支持数万条目不卡顿；② `--json` 逐行解析放线程池，不阻塞事件循环；③ SQLite：WAL + 单写连接 + busy_timeout=5000；④ 备份限速：策略字段 `--limit-upload/--limit-download`（KiB/s，0=不限）+ 进程级 nice/ionice 作 IO 优先级补充，P2 交付（Q5 已裁决） |
| **可用性** | ① 任务失败/skipped/锁残留/ro 档限制/pg 版本不匹配等，一律在 UI 给出明确原因与下一步动作，禁止静默失败；② 手动触发冲突返回 409 并提示"已有任务进行中"；③ 页面刷新不丢进度（日志尾部回放 + 续流）；④ 容器重启：running 标记 interrupted + 按策略补跑 + AUTO_UNLOCK 语义处理锁残留 |
| **兼容性** | ① 浏览器：支持 Chrome/Edge/Firefox 最近两个大版本 + Safari 最新版（需支持 EventSource 与 CSS 虚拟滚动方案）；**不支持 IE 及已停止安全更新的浏览器版本——支持/不支持清单写入部署文档（Q8 已裁决）**；② restic `--json` 字段随版本演进，解析层做版本适配（镜像固定版本，fixture 回归测试兜底）；③ 单实例部署，禁止水平扩容多副本（文档声明）；④ 界面语言：首版即中英双语，i18n（vue-i18n）架构 P1 预留（Q3 已裁决） |

## 7. 组件库选型（已裁决：Vue 3.5 + Naive UI）

**结论：已裁决 Naive UI（2026-10-10），与 Vite + Vue 3.5 配套使用**（Vue 3.6 目前处于 RC/Vapor Mode，不采用，待其稳定后可再评估升级）。

| 考量维度 | 评估 |
|---|---|
| 框架匹配 | Vue 3 原生组件库，专为 Vue 3 设计，无跨框架移植层；全量 TypeScript 编写，类型定义与 Vue 类型体系（SFC / `defineProps` / `defineEmits`）天然一致 |
| 表格/表单/向导类交互密集 | 强匹配：`n-data-table`（分页/筛选，内建 `virtual-scroll` 虚拟滚动）、`n-form`（联动/校验/脱敏字段禁用态）、`n-steps`（恢复向导/首启引导）、`n-modal` / `n-popconfirm`（三重确认弹窗）开箱即用 |
| 暗色模式 | 内置 `darkTheme`，经 `n-config-provider` 一行切换；自托管运维场景常驻服务器机房/夜间使用，暗色为实际需求 |
| 许可与体积 | MIT 许可，无商业组件陷阱；支持 tree-shaking 按需打包，组件样式内聚（CSS-in-JS），无全局样式污染，不打劫全局 CSS 命名空间 |
| 生态与本项目匹配 | 中文文档完善；SSE 进度用 `n-progress` + 自研 composable 订阅层即可，EventSource 为浏览器原生，无组件库依赖 |
| 备选对比 | Element Plus：生态体量大、Vue 3 组件最全，但设计语言偏移动端风格、按需引入配置较重（需 unplugin 系列插件）；Ant Design Vue：AntD 的 Vue 移植，能力齐全但暗色主题支持弱于 Naive UI。Naive UI 对"管理后台型表单密集 + 需要暗色"场景最匹配 |

配套约定：虚拟滚动列表（快照/文件树）优先用 `n-data-table` 的 `virtual-scroll` 属性，非表格场景（懒加载文件树）用 `@vueuse/core` 的 `useVirtualList` 兜底；SSE 统一封装为 Vue composable（`useJobStream`），组件不直接持有 EventSource。
