## 0. 需求复述与边界

### 0.1 需求定义（owner 已裁决，直接采用）

同仓库下 N 个备份任务，每个任务绑定：**源集合 + tag + 策略**（cron / keep_* / one_file_system / compression / 限速等字段）；仓库级**串行**互斥（由 restic 锁决定：手动冲突 409、调度冲突记 cancelled + audit）；仪表盘改为**任务卡片列表**（每项：名称/状态/上次运行/下次运行/Start/进度/日志入口）。Duplicati 对齐的 **A 档 UI（新建/编辑任务向导）并入本需求**实现；**B1 文件级恢复（restic `--include`）随 P2 同批**纳入需求池。

### 0.2 边界（本增量不做）

| 不做项 | 原因 / 归属 |
|---|---|
| 多仓库管理与仓库切换器 | R-023 仍归 P3；本增量仅按 E7 带 `repo_id` 外键预留 |
| 任何覆盖语义 / 原位恢复 | 红线 S7（P1/P2 均不引入）；R-015 另行立项 |

## 2. 用户故事与验收标准

> 角色统一为「管理员」（单管理员产品）；格式与主 PRD §3 一致。

**US-026-01 创建备份任务（向导）**
> 作为管理员，我希望通过分步向导创建备份任务（名称、源集合、调度、保留），这样不同目录能按不同频率与保留策略备份。

- AC1：向导 5 步——① 基础信息（任务名称必填；运行模式说明卡；**密码文件挂载状态只读展示：已配置/缺失，无任何密码输入框**，S3）② 备份源（目录树勾选，展示宿主机原路径；内置排除集只读且强制生效）③ 存储目标（当前仓库只读 + 「测试连接」）④ 调度（cron 模板快捷填充 + 下次触发预览）⑤ 保留档位 + dry-run 扫描预览 → 确认 → 立即首跑（可「仅保存不运行」）；
- AC2：所有路径输入过 PathMapper 校验（S1），越界返回 `400 PATH_OUT_OF_PREFIX`；
- AC3：保存成功后任务出现在仪表盘卡片列表（未运行显示「从未运行」）；
- AC4：向导全文案走 i18n 中英双语，模板无硬编码中文；
- AC5：创建动作写审计（`task.create`）。

**US-026-02 编辑备份任务**
> 作为管理员，我希望编辑已有任务的源集合、cron、保留档位与启停状态，保存即时生效，这样调整策略无需重建任务。

- AC1：编辑流复用向导并预填；cron 改动由调度器动态重载、无需重启容器；
- AC2：源集合变更后任务标记「需重新预览」，下次运行前必须先过 dry-run 确认（UI 拦截 + 状态标记，不静默放行）；
- AC3：提供「启用/暂停」开关：暂停即停止调度但保留任务定义与历史（卡片显示「已暂停」）；
- AC4：tag 只读不可编辑（假设 A3，见 §5-Q3）；
- AC5：保存写审计（`task.update`）。

**US-026-03 删除备份任务（三重确认）**
> 作为管理员，我希望删除任务时有明确的影响告知与三重确认，这样不会因误删导致备份静默中断。

- AC1：第一重弹窗明示影响——将删除：任务定义与调度安排；将保留：历史任务记录、日志、仓库中该任务 tag 的快照；明示「不可撤销」；
- AC2：第二重要求输入任务名称（指定确认文本）；
- AC3：第三重二次确认弹窗（红色确认按钮）；
- AC4：全程入审计（`task.delete`，append-only）；
- AC5：运行中/等待中的任务拒绝删除（提示先取消）；删除后该任务不再参与任何调度。

**US-026-04 手动 Start 与 409 冲突**
> 作为管理员，我希望点击任务卡片 Start 立即运行该任务，并在已有任务运行时得到明确提示，而不是静默失败或损坏仓库。

- AC1：Start 提交手动备份（trigger=manual），202 后卡片内联展示 SSE 进度；
- AC2：同仓库已有 running/pending 任务时返回 `409 JOB_CONFLICT`，data 含 `running_job_id` 与任务名，UI 提示「已有任务进行中：<任务名>」，**不排队**；
- AC3：运行中任务可取消（复用 E16），终态 cancelled 并可见；
- AC4：互斥为仓库维度（E1）：多任务串行由 restic 锁决定；`JobRunner.submit` 双并发竞态测试断言恰好 1 成功。

**US-026-05 SSE 进度与日志入口**
> 作为管理员，我希望任务运行时看到实时进度、刷新页面进度不丢、日志一键可达，这样长任务期间可以放心离开再回来。

- AC1：进度经 SSE 推送（复用 E15），Last-Event-ID 断点续传；刷新后凭 job_id 重订阅，先回放日志尾部再续流；
- AC2：卡片「日志」入口打开日志抽屉（复用 E27 尾部读取），skipped 文件计数与明细可见；
- AC3：进行中任务在仪表盘与任务历史页同源可见（E13 running/pending）。

**US-026-06 仪表盘任务卡片**
> 作为管理员，我希望在仪表盘一屏看到所有任务的状态与关键时间，这样无需逐页检查备份健康度。

- AC1：每张卡片包含：任务名称、状态徽章（运行中/等待中/成功/失败/已中断/已取消/已暂停/从未运行）、上次运行时间与结果、下次运行时间（启用且有 cron 时；无 cron 显示「仅手动」；暂停显示「已暂停」）、Start 按钮、运行中进度条、日志入口；
- AC2：列表按虚拟滚动渲染（n-data-table virtual-scroll，建议见 §5-Q6）；
- AC3：空状态：「还没有备份任务」+「新建备份任务」主按钮（对齐 Duplicati A 档 checklist 入口）。

**US-026-07 任务级 cron 与保留档位**
> 作为管理员，我希望为每个任务单独配置 cron 与保留档位并如期自动执行与清理，这样不同任务有不同节奏且仓库不无限增长。

- AC1：调度器按任务全量重建触发器（cron + jitter；为空回退全局缺省），任务保存后动态重载；
- AC2：保留策略按任务 tag 执行 forget（复用 R-016 预览-确认流，`--tag` 维度），prune 到期独立判定；
- AC3：启动补跑覆盖「当天已过点未成功」的任务（R-013 既有语义按任务维度）；
- AC4：容器重启后任务状态与仓库锁恢复正确（interrupted + 补跑 + AUTO_UNLOCK 既有语义）。

**US-026-08 按 tag 的快照归组视图**
> 作为管理员，我希望快照按任务 tag 归组浏览，这样能看清每个任务各自产生了哪些快照。

- AC1：快照浏览页支持按 tag 筛选，默认按 tag 分组展示（每组：任务名、快照数、最新时间）；
- AC2：tag 与任务名映射来自任务表（tag 自动生成，见 A3）；
- AC3：列表分页/虚拟滚动不卡（复用 E17/E18 既有机制）。

**US-026-09 存量数据迁移**
> 作为管理员（升级用户），我希望现有的单默认策略与全局源集合自动变成第一个备份任务、历史记录不中断，这样升级后无需重新配置。

- AC1：`0002` 迁移 + 启动期 backfill：默认策略行全字段（cron/keep_*/group_by/one_file_system/compression/sources/excludes/限速）物化为 `backup_tasks` 首行（建议命名「默认备份」）；
- AC2：存量 jobs 记录保留且归属可追溯（保留 legacy 关联，不重写历史）；
- AC3：存量快照 tag 归属不变（原默认策略 tag 原样继承给首任务）；
- AC4：迁移幂等（重复执行不产生重复任务），失败有明确错误提示而非静默；
- AC5：迁移后首任务按原 cron 继续调度，无空窗。

**US-026-10 B1 文件级恢复（R-027）**
> 作为管理员，我希望恢复时勾选快照内的部分文件/目录精准恢复，这样不必整包落地。

- AC1：恢复向导步骤 1 增加可选文件树多选（复用 VirtualTree + E18），不选则恢复整快照（兼容既有行为）；
- AC2：后端 restore 请求体增可选 `paths`；`ResticCmd.build` 白名单内拼装 `--include`（S2，禁自由字符串）；每个 path 过 `PathMapper.validate`（S1）；
- AC3：确认门预览展示所选文件清单；
- AC4：目标仍为自动时间戳子目录（S7，无任何覆盖语义）；`restore.run` 审计既有埋点覆盖（S6，不新增动作名）。

### 4.1 仪表盘任务卡片

卡片结构（自上而下）：标题行（任务名 + 状态徽章 + 「⋯」菜单：编辑/删除）→ 元信息行（上次运行/下次运行）→ 进度区（running 时：进度条 + 百分比 + 文件数 + 字节数 + 「取消」；终态时：结果摘要 + skipped 计数，skipped>0 醒目提示）→ 操作行（「立即运行」主按钮，running 时置灰 + 「日志」按钮）。

```text
┌──────────────────────────────────────────────────┐
│ 每日全量                        [运行中]   ⋯ 编辑/删除 │
│ 上次运行：10-12 03:00 · 成功                       │
│ 下次运行：10-13 03:00                             │
│ ████████████░░░░░░ 62% · 3,210/5,178 文件 · 1.2 GiB │ [取消]
│ [立即运行]                        [日志]           │
└──────────────────────────────────────────────────┘
```

### 4.2 新建/编辑任务向导（n-steps 五步，顺序对齐 Duplicati）

| 步骤 | 标题（zh / en） | 元素与交互 |
|---|---|---|
| 1 | 基础信息 / Basic | 任务名称（必填，占位「每日全量」/ "Daily full"）；运行模式说明卡（当前 运行用户×挂载模式 组合，复用 QuadrantCard）；**密码文件挂载状态：已配置/缺失**（只读，无输入框） |
| 2 | 备份源 / Source data | 目录树勾选（宿主机原路径展示，虚拟滚动）；内置排除集只读展示（强制生效）；追加排除规则输入；提示「首次备份最慢属预期」/ "The first backup is the slowest — this is expected." |
| 3 | 存储目标 / Storage destination | 当前仓库地址只读展示；「测试连接」按钮 + 结果反馈（失败明示原因，禁止静默） |
| 4 | 调度 / Schedule | cron 输入 + 常用模板快捷填充（每天 03:00 / 每小时 / 每周一 03:00 / 每月 1 日）+ 下次触发时间预览；jitter；「不调度（仅手动运行）」选项 |
| 5 | 保留与首跑 / Retention & first run | keep_last/hourly/daily/weekly/monthly/yearly 档位；「预览扫描范围」（dry-run）→ 扫描清单 + 警告 → 「确认并立即首跑」或「仅保存，稍后手动运行」 |

编辑流：复用同一向导、预填现有值；第 5 步dry-run 门在源集合变更后再次出现（US-026-02 AC2）。

## 6. 关键假设（PM 假设，待 owner 确认）

- A1：任务与策略 1:1（任务即策略）——若 owner 选 1:N，数据模型与迁移设计需返工；
- A2：源集合纯 per-task，无「全局默认 + 任务覆盖」两层；
- A3：tag 自动生成且用户不可编辑；
- A4：存量迁移为「默认策略行 → 首个任务」，不重写历史 jobs；
- A5：删除任务不删快照/历史（只解绑），运行中任务不可删除；
- A6：B1 的 `--include` 在既有 `ResticCmd.build` 白名单机制内扩展，不新增自由字符串通道；
- A7：所有新端点默认 `require_session` + Origin 校验（S4），E 编号由架构师/owner 定稿后同步架构文档 §5.1；
- A8：全局缺省 cron/jitter 保留在 config（`schedule.*`），任务级为空时回退。
