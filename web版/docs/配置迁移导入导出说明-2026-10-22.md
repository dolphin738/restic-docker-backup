# 配置迁移（导入 / 导出）说明

> **状态**：过程层说明文档，2026-10-22 整理（owner 指令：把配置迁移导入/导出的解释存档）。
> **规格权威**：`docs/架构设计文档.md` v1.6-E（2026-10-18，批次 E = 配置导入/导出）；唯一实现 = `backend/app/services/config_transfer.py` + `backend/app/routers/ops.py`。
> 本文是蒸馏后的使用者向说明（非讨论原文）；与权威文档/代码不一致时，以后者为准。

## TL;DR

- **是什么**：把「仓库清单 + 全部备份任务 + 行为/通知配置 + 凭据」打成一个 JSON 包，用于换机、重装、多环境复刻配置。**只搬配置，不搬快照数据本身**。
- **凭据是加密的**：凭据段用导出口令（≥10 位）经 PBKDF2-HMAC-SHA256 60 万次迭代派生密钥、AES-256-GCM 加密；错口令或文件被篡改 → 拒绝导入，绝不静默通过。
- **导入讲匹配不讲覆盖**：仓库按 id、任务按 `(仓库, 任务名)` 匹配；默认冲突跳过并出报告，确认要覆盖才开 `replace_existing`。
- **有些列故意不带**：任务 id、tag、创建/更新时间、上次运行时间等「跨机不可带」列，导入时剔除——带回会谎报状态，甚至直接 500（见 §5）。
- **审计留痕**：导出/导入各记一条 `config.export` / `config.import`，detail 只含计数，绝不含凭据或包原文。

## 1. 这个功能解决什么问题

在 A 机上调好的一套配置（有哪些仓库、每个仓库跑哪些备份任务、保留策略、行为开关、通知渠道、各仓库凭据），想原样搬到 B 机（换机器、重装系统、测试环境复刻）。逐项手抄容易漏，本功能把配置打成一个包、口令加密后带走。

- UI 位置：**设置页 → 「配置迁移（导入 / 导出）」卡**（需登录）。
- 接口：`POST /api/config/export`（下载 JSON 文件 `restic-web-config-<日期>.json`）/ `POST /api/config/import`。

## 2. 导出：一个文件里带走什么

包格式 `restic-web-config-export` v2（2026-11-02 起；v1 包仍可导入），分**明文段**与**加密段**。

| 进包内容 | 所在段 | 说明 |
|---|---|---|
| 仓库清单 | 明文 | 每仓 `id/name/url/host_tag`——只搬「仓库是谁、指向哪个存储」，不搬仓库里的数据 |
| 全部备份任务 | 明文 | 各仓全部任务的完整配置（调度、保留策略、镜像引用等） |
| `behavior.*` 配置 | 明文 | 行为开关（如定期校验相关） |
| `notify.*` 非敏感键 | 明文 | 通知渠道配置（如 SMTP 服务器地址、端口） |
| 凭据 | **加密段** | `cred.*`（各仓库相关凭据，如 restic 仓库密码）与敏感 `notify.*` 键（如邮件密码） |

**不进包的内容及理由**：

| 不进包 | 理由 |
|---|---|
| `dump.*` | 本机数据库 dump 配置，跨机语义弱 |
| `security.*` | 加密开关由目标机自管 |
| 其余一切配置键 | 导出只取 `behavior.*` / `notify.*` / `cred.*` 三族，其余一概不进包 |
| 审计日志、作业历史 | 每机独立留痕，不混入他机历史 |
| 快照与仓库数据 | 本功能只搬配置；数据在 restic 仓库里，B 机指向同一存储即可见 |
| 密码文件 | 凭据以加密配置项形式迁移，不搬 `<passfile_root>/<repo_id>/password` 文件本身 |

## 3. 凭据为什么是加密的

包里带全部凭据，文件一旦泄露后果严重，因此：

- **口令要求 ≥10 位**（与仓库密码口径对齐——它保护的是全部凭据）；
- **密钥派生**：PBKDF2-HMAC-SHA256，60 万次迭代（OWASP 2023 建议）；
- **加密**：AES-256-GCM（认证加密，带防篡改标签）；
- **salt 每次导出随机**：同一口令导出两次，密文不同，抗彩虹表；
- **错口令 / 文件被篡改**：GCM 认证标签校验失败 → 明确报「导出口令错误（或文件被篡改）」，导入中止，绝不静默通过；
- **内存纪律（S3）**：明文凭据只存在于加密前后的内存瞬间，不进日志、审计、异常信息；
- 包带 `format` + `version`；**导出恒为最新版（当前 v2），导入接受 `{1, 2}`**，集合外的版本拒绝导入；未来结构变更只增 version。
- **v2 新增（2026-11-02）**：加密段内并列 `degraded` 映射（键 → 失效原因）。当某仓库的密钥源（口令文件）失效时，它保护的凭据**读不出来**，导出包里对应值为空——v1 包里这与「本来就没配过」不可区分，接收端会静默丢凭据。v2 把这些键单独记进 `degraded`，接收端据此可提示「这些凭据在源机已失效、需重新录入」。**该映射位于加密段**：键名本身即暴露「源机配过哪些凭据」，不放明文段。

## 4. 导入：数据怎么落位

导入顺序固定为**先仓 → 凭据 → 任务**——因为任务归属、镜像引用、凭据键都按仓库 id 串，仓不先落位后面全悬空。

**仓库按 id 匹配**（四种结局）：

| 目标机情况 | 默认结局 | `replace_existing=true` 时 |
|---|---|---|
| 该 id 不存在 | 新建（用包内 name/url/host_tag） | 同左 |
| 同 id 同 url | 复用现有仓，不动 | 同左 |
| 同 id 不同 url | **跳过**，报告记原因 | 更新为包内 name/url/host_tag |

**任务按 `(repo_id, name)` 匹配**：

| 目标机情况 | 默认结局 | `replace_existing=true` 时 |
|---|---|---|
| 该仓无同名任务 | 新建（跨机不可带列剔除后落库，见 §5） | 同左 |
| 已有同名任务 | **跳过**，报告记原因 | 以包内版本整体替换 |

**镜像引用（`mirror_repo_ids`）**：指「备份成功后把快照复制到其他仓库」的目标仓 id 清单。接上前校验两条：① id 在包内仓库清单中；② 目标机该仓最终 url 与包内一致。任一不满足 → **置空 + 报告警告**——绝不静默指向一个不相干的仓（防止快照被复制到错误存储）。

**凭据**：从加密段解出后，只写入 `cred.<本次导入的仓 id>.*`——包里其他仓的凭据不带过来（那些仓可能被跳过）。被环境变量覆盖或只读的键 → 记警告，不中断整批。

**通知配置**：明文段非敏感 notify 键 + 加密段敏感 notify 键，合并写入。

**导入报告**（前端逐项展示）：仓库 created/reused/updated/skipped、任务 created/updated/skipped、镜像警告、凭据写入数、通知键写入数。冲突默认跳过就是为了「先看清楚报告，再决定是否覆盖重来」。

## 5. 「跨机不可带的列」逐项解释

导出包里任务带着原机器的完整字段，但其中一些列的值**只对原机有意义**（属于原机的主键空间或时间线），导入时一律剔除，由目标机按自己的规则生成：

| 列 | 包里的原值 | 导入时处理 | 为什么 |
|---|---|---|---|
| `id` | 原机任务自增主键 | 剔除，不用 | 目标机主键空间独立，带入会撞 id/错位；任务按 `(repo_id, name)` 匹配后，新建得目标机新 id，已存在则更新旧行 |
| `tag` | 形如 `task-<原机id>` | 剔除，目标机回写 | tag 由 id 回写生成，绑定原机 id，同样不可带 |
| `repo_id` | 导出方的仓库归属 | 剔除，按仓匹配结果重设 | 以目标机实际落位仓为准，不信任包内归属 |
| `created_at` / `updated_at` | 原机创建/更新时间 | 剔除，目标机自生成 | 原机时间戳对目标机无意义，带入会污染时间线 |
| `last_run_at` | 原机上次运行时间 | 剔除，置空 | 目标机没有这条任务的执行历史；带入会**谎报「上次备份时间」**（页面显示几月前备份过，实际这台机器从未跑过） |
| `dry_run_pending` | 原机草稿待确认标记 | 按 0 落库 | 导入不是待确认的新建草稿 |
| `host_tag` | repos 表字段（被任务 dict 形态带进包） | 剔除 | `backup_tasks` 表无此列；不剔除会在 create 路径的列校验处直接 500——2026-10-18 真机 E2E 实证：update 路径不校验故覆盖导入能过，新建（异地导入/新任务名）必炸 |

一句话：**包可以跨机带「配置」，不能跨机带「身份与历史」**。

## 6. 审计与留痕

- `config.export`：记仓库数、任务数、配置键数、凭据数；
- `config.import`：记同类计数 + `replace_existing` 取值；
- detail 绝不含凭据或包原文（S3/S6 合规；本功能占 S6 危险操作清单第 13/14 项）。

## 7. 使用建议

1. **导出**：旧机设置页 → 配置迁移 → 设口令（≥10 位，建议密码管理器保存）→ 下载 JSON 包。
2. **导入**：新机同页 → 选文件 → 输同一口令 → 先按默认「冲突跳过」导一遍，**逐项看报告**；确认要覆盖再开 `replace_existing`（前端有确认闸）重导。
3. **口令即凭据的钥匙**：丢了口令 = 加密段无法恢复（GCM 无后门），只能回旧机重新导出。
4. **包只搬配置不搬数据**：restic 仓库指向同一存储时，历史快照直接可见；指向新存储则需要另行首次备份。
5. **同 id 不同 url 的仓默认跳过**：这是防呆设计——目标机已存在同 id 仓且指向别处时，不声不响改 url 是危险的。
