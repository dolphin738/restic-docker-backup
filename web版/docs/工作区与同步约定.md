# 工作区与同步约定

> 建立：2026-11-01。主从反转：此前 WSL 为开发端、Windows 为副本；现 **Windows 端为唯一开发点**，WSL 仅作测试用途。

## 1. 主从关系

| | Windows 端（主） | WSL 端（测试从） |
| --- | --- | --- |
| 路径 | `D:\agent\AI Coding\restic-docker-backup\web版` | `/home/AI-Coding/restic-docker-backup/web版`（经 9P `/mnt/d` 可见） |
| 角色 | 开发、提交、推送 | 仅运行测试与红线校验 |
| git | 本地主副本，remote 含 github / cnb.cool | 跟踪 github，不在此开发 |

## 2. 开发流程

- 所有源码修改、提交（Conventional Commits、按特性拆分、单次 <=400 行 diff）在 **Windows 端**完成；AI 在 Windows 端实现，由负责人（`restic-web-dev <dev@local>`）审查合并。
- WSL 侧**不承载开发、不提交**；其工作树仅用于跑测试，测试结论回 Windows 端落盘。

## 3. 测试时同步到 WSL（本地复制，不走远端）

需要测试时，把 Windows 端源码同步到 WSL 跑测试：

```bash
rsync -a --delete \
  --exclude node_modules --exclude .venv --exclude .git \
  --exclude dist --exclude __pycache__ \
  "/mnt/d/agent/AI Coding/restic-docker-backup/web版/" \
  "/home/AI-Coding/restic-docker-backup/web版/"
```

要点：
- 只拷源码 + 锁文件（`pnpm-lock.yaml` / `uv.lock`）；依赖在 WSL 侧原生 ext4 重新 `pnpm install` / `uv sync` 一次，避开 9P 的符号链接与 `.git/index.lock` 争用。
- 复制进 WSL 的文件表现为「未提交改动」，**仅用于跑测试，不在 WSL 提交**。
- 轻量单测也可直接在 `/mnt/d/...` 挂载路径跑，但全量回归（pytest 1273 / vitest 539）须在 WSL 原生 ext4 工作树进行（9P 下大量小文件 IO 慢且易撞锁）。

## 4. 授权约束

依仓库工作流，AI **不自行执行 push / sync / 跨工作树写入**等工作副本改动操作；任何实际同步或 git 写命令前须获负责人明确授权。

## 5. 推送说明

- Windows 端 `origin` = cnb.cool，`github` = github.com。推公开远端走 `git push github main`（WSL 侧 `gh auth setup-git` 已配凭据助手）。
- 推送前按交接纪律核对：无 `.env`、无密钥、无大文件入库（`git log --stat` 抽查）。
