## 1. 设计原则：从代码证据出发

「符合用户习惯」不靠猜测——以下四条原则每条对应当前代码里已形成的行为惯性，新设计是**强化**这些习惯，而非推翻。

| # | 原则 | 说明 | 证据 |
|---|---|---|---|
| 1 | 状态先行 | 备份工具的核心焦虑是「我的备份现在好吗」。仓库连接状态、运行中任务数已在顶栏常驻并以 15s 轮询刷新；仪表盘首屏即仓库状态卡。新设计升级为**全站统一状态带** | `BasicLayout.vue:213-240`；轮询节奏见 `架构设计文档.md:1465` |
| 2 | 危险操作设门，日常操作零打扰 | 原位恢复、`forget --prune` 等高危动作统一走 `ConfirmGate`；浏览、筛选、切仓库从不弹窗。固化为三级手势：读操作随手 / 写操作设门 / 不可逆操作设双门 | `components/ConfirmGate.vue`；红线 S6/S7（`代码审查规范.md` §3.1） |
| 3 | 技术用户的密度偏好 | 用户是 self-host 技术人群：快照 id、容器路径、cron 表达式以等宽字体呈现才扫读得快。硬规则：**数据区等宽、说明区可读** | `components/VirtualTree.vue`、`PathBreadcrumb.vue`；用户画像见 `Web版PRD.md:33-41` |
| 4 | 深色优先、双语并行 | 主题三态（dark/light/auto）与中英切换已是顶栏一级入口，暗色 token 为独立调校而非反色。深色为默认观感基调，两语言下文案留足伸缩空间 | `App.vue:15,20`、`BasicLayout.vue:242-257`、`i18n/index.ts:7` |

## 3. 字体 / 间距 / 圆角 / 阴影

### 3.1 字体

| 用途 | 字体栈 | 规则 |
|---|---|---|
| 界面正文 | `v-sans, system-ui, -apple-system, 'Segoe UI', 'PingFang SC', 'Microsoft YaHei', sans-serif` | 维持 `App.vue:50-51` 现状，**不引入 webfont**（self-host 场景零外网依赖） |
| 数据 / 路径 / id / cron | `Consolas, 'Cascadia Mono', monospace` | 快照短 id、容器路径、文件大小、cron 一律等宽 |

**等宽字体现状有 4 处硬编码，须收口**：`components/task/ScheduleRetentionForm.vue:413`、`pages/audit/index.vue:260`、`pages/jobs/index.vue:708`、`pages/repo/index.vue:1264`。做法：在 `tokens.ts` **新增 `fontFamilyMono` 导出**（当前该文件只导出两个 `common` 段，无 `fontFamily` 也无 `fontFamilyMono`，且注释明确「不设 fontFamily」——新增导出需同步改注释），4 处改为引用该常量。

字号阶梯：12（辅助）→ 13（表格/表单）→ 14（正文默认）→ 16（卡片标题）→ 20（页面标题）→ 28（KPI 数字）。

### 3.2 间距（4px 基数，8 的倍数为主）

| 标尺 | 值 | 用途 |
|---|---|---|
| space-1 | 4px | 图标与文字间隙、标签内边距 |
| space-2 | 8px | 关联元素组内间距（表单字段间） |
| space-3 | 12px | 卡片内边距（紧凑区）、网格 gap（现状任务卡 gap 12px，`dashboard/index.vue:83`） |
| space-4 | 16px | 卡片标准内边距、顶栏水平内边距（现状 16px 保留） |
| space-6 | 24px | 区块之间（页内分节） |
| space-8 | 32px | 页面内容区留白（现 content padding 20px → 24px，`BasicLayout.vue:260`） |

### 3.3 圆角与阴影

- **圆角**：卡片/弹窗/输入框 8px（`borderRadius`，现值 5px，`tokens.ts:41`）· 小元素 999px 全圆 · 按钮 6px（`borderRadiusSmall`，现值 3px）。
- **阴影**：亮色主题用阴影分层（卡片 `0 1px 3px rgba(15,23,42,.08)`，弹层 `0 8px 24px rgba(15,23,42,.14)`）；**暗色主题不用阴影，靠 `cardColor` 与 `borderColor` 两档亮度差分层次**——这是暗色「发灰糊一片」问题的解法。现状全仓无 `box-shadow`（`TaskCard.vue:171` 注释亦写明「无阴影」），暗色引入阴影反而破坏分层。

### 4.4 响应式断点

**不改断点数值**：桌面 ≥960px 侧栏常驻（可折叠 64px）、<960px 转左抽屉 240px，均由 JS `useMediaQuery('(max-width: 959px)')` 控制（`BasicLayout.vue:59`，全仓无 `@media`，新增样式须沿用 JS 断点或在同一批内明确引入 CSS 媒体查询策略）。

## 6. 核心组件规范

### PV-1 · NMenu 折叠态下分组会散掉

- **现象（P0 已实证，结论见本节末）**：按 Naive UI 文档，`NMenu` 折叠态只渲染一级菜单（图标 + 悬浮提示），`type: 'group'` 的组标题不参与该层渲染——即分组信息在折叠态可能整体丢失；若改用 `submenu` 承载分组，折叠态会变成 popover，交互语义随之改变（点一下先弹层再选，多一步）。
- **证据**：现折叠行为 `BasicLayout.vue:187-196`（`collapse-mode="width"`、64px）；菜单为 `NMenu` + 内联 SVG 图标（`:69-71,201-208`）。
- **候选解法**（须先做最小验证再动代码）：
  1. 折叠态切回扁平一维数组，展开态用分组——数据源按 `collapsed` 派生两套 `menuOptions`；
  2. 用 `submenu` 承载分组，折叠态变 popover，需重新验收「展开/收起 + 选中」手势；
  3. 保留分组，折叠态仅显示图标 + tooltip，组归属靠 tooltip 前缀表达。
- **验收**：折叠/展开切换后选中态（`.n-menu-item-content--selected` class——naive-ui 2.45.3 无 `aria-current`，实测契约即 class）、键盘可达、i18n 键无缺失均不回归；不出现「折叠后某菜单项消失」。
- **落地批次**：**P0 已跑完并选定候选 1**（2026-10-18 运行时最小样例，临时文件已丢弃）→ **P2** 在 `BasicLayout.vue` 落地。

> **P0 实证结论（2026-10-18，naive-ui 2.45.3）**：选定**候选解法 1**（折叠态派生扁平数组、展开态用分组）。
> - 机制校正：折叠态并非「组标题不渲染」——`MenuOptionGroup` 无条件渲染组标题，CSS `.n-menu--collapsed` 只隐藏 `.n-menu-item-content__header`（文字 opacity 0），**组标题会以文字形式残留在 64px 窄栏**；
> - 数据实测：折叠 + 分组 = 9 子项全在 + 4 个组标题残留；折叠 + 扁平 = 9 子项、0 组标题，与现状已 QA 复验的折叠行为逐点一致（含选中态恰 1 项）；
> - 结论：候选 1 零手势改动、零回归面，直接落地 P2。

> **P0 定稿记录（2026-10-18，源码 + 运行时双重实证）**：**NDropdown**（图标按钮触发 + 三选项 + 当前值勾选）。
> - 键盘：`Dropdown.mjs:105-129` 内置 `useKeyboard` 全映射（ArrowUp/Down/Left/Right/Enter/Escape，vooks 监听 document，打开时启用）；**NPopselect 自身源码零 keydown 处理**（运行时对照实测：打开后 ArrowDown+Enter 不产生任何选择）；

## 11. 从「2026 趋势版」吸收的 3 项

趋势版的整体骨架不采纳（理由见 §12），但其中三项零件成本低、收益明确，纳入本方案。

> **归属批次（对应 §9.1）**：AB-1 → **P1**；AB-2 → **P4**；AB-3 → **P5**（可选，前置 PRD 立项）。三项均已排入批次，不存在悬空条款。

### AB-1 · 等宽数字 `tabular-nums`

- **做什么**：全局工具类 `.tabular-nums { font-variant-numeric: tabular-nums; }`，用于 KPI 数字、表格数值列、进度百分比、容量/大小。
- **理由**：轮询每 15s 刷新数字，非等宽字宽会导致列跳动。现状全仓 `tabular-nums` / `font-variant-numeric` **零命中**。
- **成本**：`App.vue` 一段样式 + 若干处 class 追加。**随 P1 一起交付**（见 §9.1）。

### AB-2 · KPI 数字 count-up

- **做什么**：KPI 状态带数字进入视口时滚动到位（一次性）。
- **边界**：仅 KPI 首屏数字；`prefers-reduced-motion` 时直切；不阻塞首屏渲染、不与 15s 轮询刷新冲突（刷新只更新目标值，不重放动画）。
- **成本**：一段 `requestAnimationFrame` 逻辑，无新依赖。**随 P4 仪表盘批次交付**（见 §9.1）。

> **落地情况（P4，2026-10-19）**：`composables/useCountUp.ts`——`useCountUp(target: Ref<number>): Ref<number>`，`ease-out` 缓动、一次性播放；首帧不播（避免数据后到时已置位 `played`）、`prefers-reduced-motion` 直切、卸载即 `cancelAnimationFrame`。已接入仪表盘「仓库容量」「快照数」两处；走查断言两者收敛为终值（320.0 GiB / 142）。

### AB-3 · ⌘K 命令面板（**需先立项**）

- **做什么**：全局快捷键唤起的命令面板，支持页面跳转（中英别名匹配）、任务定位、仓库切换。
- **前置（硬性）**：
  1. **PRD 需求池无此项**（`Web版PRD.md` 未覆盖命令面板），须先按 `文档管理规范.md:40` 在 PRD 增补需求条目，再由本方案细化；
  2. 首版**不做写操作**——「立即运行」等动作不得进面板，避免在面板里新开一个绕过 `ConfirmGate` 的入口（红线 S7）；如需纳入，必须内联二次确认且标注快捷键；
  3. 键盘焦点圈闭 + Esc 关闭 + 中英别名匹配 + 空结果提示；
  4. **不引入第三方库**（模糊匹配自实现）。
- **成本**：约 250–350 行（组件 + i18n + 焦点管理），独立成批。
- **归属批次**：**P5**，**不阻塞 P0–P4 任何一步**。

## 12. 明确不采纳（趋势版整体骨架）

| 不采纳项 | 理由 | 证据 |
|---|---|---|
| Dock 纯图标导航（72px，无文字标签） | 该项目是**低频**自托管工具（`Web版PRD.md:33-41` 用户画像：家用 NAS 个人玩家 / 小团队运维）。低频使用者的图标记忆最弱，恰恰最需要文字标签；移动端无 hover 可用。原方案以「低频所以可接受学习成本」论证，方向相反 | `BasicLayout.vue:74-84`（现 9 项带文字标签） |
| Bento Grid 首屏 | 7 块瓦片中「近 30 天备份量 sparkline」「存储趋势净增」**无数据源**：后端仓库状态只出 `capacity` / `last_error`，无时间序列与净增统计；补齐需扩后端契约，与「不动 API 契约」前提冲突。去掉这两块后 Bento 退化为普通卡片栅格，失去「面积=重要性」的立论 | `backend/app/routers/repos.py:560,615-617` |
| 玻璃拟态（backdrop-filter） | Naive UI `themeOverrides` 无玻璃 token，`backdrop-filter` 只能覆写 `.n-modal-card` / `.n-drawer` 等内部类，属分散 CSS 覆写，破坏「令牌单一来源」；且需为低端 GPU 再造降级分支 | 全仓 `backdrop-filter` / `blur(` 零命中 |
| 渐变主色 + 发光状态点 | ① `primaryColor` 只接受单色，渐变必须逐组件覆写按钮样式，「P1 纯 token 零结构改动」不成立；② 项目定位是「安静可靠」——深色界面里「光」应是最贵的资源，全站铺发光与备份工具的日常心境不符；③ 状态点发光需要新增 `StatusDot` 组件并铺到全部状态表达处 | `tokens.ts` 仅 `common` 段；全仓 `box-shadow` 零命中 |
| 断点体系重写（Dock → 底部 Tab Bar） | 会推翻已通过 QA 复验的 <960px 抽屉行为（`Web版PRD.md:263`），且现状断点为 JS `useMediaQuery`（非 CSS），重写面大 | `BasicLayout.vue:59` |
| 全量重写 `BasicLayout.vue` | 违反「增量改动、避免全部重写」与单批 ≤400 行；布局层无 spec 覆盖，重写的回归成本高于收益 | `代码审查规范.md:213` |

> 保留态度：若将来后端提供快照时间序列（`stats` 历史），Bento 与容量环形进度可重新评估——**先有数据，再谈布局**。
