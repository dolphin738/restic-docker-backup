## 3. ✅ 亮点

1. **C1 钩子的设计自觉**：pre 失败阻断后续阶段（「钩子没冻结应用就备份了半截文件」的动机写进了 docstring）、post 失败也计 failed（静默吞掉=运维误以为后续动作完成）、输出截断留头（方便看命令行与首错）、`shlex.join` 回显（可复制执行）；
2. **C3 重试预算的手动豁免**：手动触发恒 0 次——「用户点立即运行是立刻要看结果，自动重试会变成长任务且进度条二次回卷」——体验动机写透；
3. **A7 语义差异如实标注**：Duplicati `--overwrite=false` 实为「冲突时改名另存」（带 Duplicati 源码行号证据），restic 无等价能力取最接近的 `never`——规范的「如实标注」纪律在实现侧得到延续；
4. **rclone.py 沿 dump.py 先例**：exec 不经 shell、超时 kill、conf 只读探测；
5. **key.rotate 的 S3 纪律**：新密码只经请求体与临时文件（mkstemp），不进 argv/日志/审计。

## 4. 🟡 Suggestion（1 项）

- **S-1 key.rotate × R-025 跨模块缺口（数据可用性）**：`ops.py rotate_repo_key` 成功后重写口令文件，但**未触发该仓库凭据的重加密**——R-025 凭据密钥由密码文件派生（`(mtime_ns, size)` 缓存即时失效），口令文件一换，该仓库命名空间的存量 `enc:v2` 凭据全部解不开，后续任务在取凭据时才 500 `CREDENTIAL_DECRYPT_FAILED`，用户须逐键经 E07 重录。与 R-025 首版自查抓出的「恢复路径」缺陷同族。建议修法（顺序敏感）：rotate 成功后**先**用旧密钥把该 repo 敏感键解出 → **再**重写口令文件 → **再**用新密钥重加密写回（三步任一失败即回滚口令文件或显式告警）。复杂点如实标注：per-repo CredentialCrypto 未落地（当前单实例 default）——rotate 非 default 仓库不影响凭据解密，rotate **default** 仓库必触发本缺口；修 per-repo 加密时一并收敛。
