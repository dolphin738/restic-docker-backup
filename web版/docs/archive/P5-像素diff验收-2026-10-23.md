> 归属：UI 全量改造方案 **§4.7 P5 验收门**（「全站基线截图存档 → 改后桌面零漂移像素 diff + 亮/暗双模式截图」）。
> 缘起：P5 交付时该验收门**无任何留痕**（仓库无基线截图、`light/` 为空），owner 2026-10-23 裁决 **A8 选①：补做并存档**。
> 结论一句话：**8 个页面 × 亮/暗双模式，页面总高零漂移（Δh 全为 0）；变化像素占比 0.40%–25.86%，全部落在令牌层预期项（圆角/密度/行高/阴影/标签边框/间距），未发现裁切、溢出或布局断裂。**

## 1. 方法（可复现）

| 项 | 取值 |
|---|---|
| 基线（改前） | git worktree @ `664ea48`（P4 收尾，P5 的父提交） |
| 改后 | 同一 worktree `git checkout 99375a4`（P5 提交本体） |
| 渲染环境 | Vite dev server（两版各自 `:5174`），Edge headless |
| 视口 | 1440 × 960，`fullPage` 截图，`deviceScaleFactor=1` |
| 数据 | `addInitScript` 注入 deterministic `/api/*` stub（同一份 3 任务/8 快照种子；不依赖后端与登录态） |
| 主题 | `rw.theme` = `light` / `dark` 两轮，各一套 |
| 动画 | 注入 `animation:none;transition:none`，避免 count-up / fade 造成不可比 |
| diff 口径 | 三通道差值 → 灰度，**阈值 8/255** 过滤抗锯齿噪声；统计变化像素占比 + bbox，并生成左右并排图（右侧差异染红） |

页面清单（覆盖 P5 令牌层全站影响面）：`dashboard` `/`、`repo` `/repo`、`settings` `/settings`、`jobs` `/jobs`、`snapshots` `/snapshots`、`restore` `/restore`、`audit` `/audit`、`notifications` `/notifications`。

复现：

```bash
git worktree add .p5-baseline 664ea48            # 基线

node web版/scripts/p5_pixdiff.cjs --base http://localhost:5174 --out p5-after-light --theme light
node web版/scripts/p5_pixdiff.cjs --base http://localhost:5174 --out p5-after-dark  --theme dark
python web版/scripts/p5_pixdiff_compare.py           # 出报告 + 并排图
```

## 5. 局限（如实标注）

1. **dev 模式截图**：未覆盖生产构建下 CSS 注入顺序的差异（cssr 运行时注入位置）。P14 全站回归须在生产构建上复跑一次。
2. **数据为 stub 种子**：不覆盖空态/错误态/长文本等边界页面；这些由既有页面 spec 与 P12/P13 逐页走查承担。
3. **「零漂移」口径**：P5 本身就是形态变更批次，像素级必然有变化；本验收的实际口径是「**总高零漂移 + 变化全部可归因 + 无裁切溢出**」，而非「像素完全相同」。原验收门表述「桌面零漂移像素 diff」在此解释下才可执行，后续批次（P12/P13）沿用同一口径与同一套脚本。
