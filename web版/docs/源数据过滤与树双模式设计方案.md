# 源数据过滤与树双模式设计方案

> 版本 v1.1（2026-10-24）
> 状态：**已实施**——批次①（部署形态检测）、批次②（过滤条件，含探针结论）、批次③（挂载点快跳/徽章 + 树标记排除 ⊘）均已落地
> 结论一句话：**放弃照搬 Duplicati 14 项过滤分类，按 restic 原生表达力重新设计**（快捷排除卡 + 有序规则列表 + 树双模式）；部署形态（Docker/主机）自动检测决定源树的浏览根。

---

## 0. 背景与决策链

1. owner 要求对齐 Duplicati「编辑备份任务第二步（源数据）」的过滤条件 UI。
2. 取证结论（2026-10-23/24，restic 0.18.0 真机探针 + 官方文档）：Duplicati 14 项过滤类型里
   **只有 3 项能语义等价落到 restic，2 项近似但会误伤，9 项做不到**。根因是 Duplicati 用自研
   filter 引擎（正则 / include / 文件组 / `[.*x[^/]*]` 私有语法），restic 只有 Go glob exclude
   + `!` 负向。照搬下拉外观会让用户以为等价，实际"排错 / 漏排 / 备份直接 Fatal"。
3. 方案对比（A / A+C / B 三案）后 owner 采纳方向：**原生重设计**——不做分类下拉，
   把 restic 自己的"有序 glob 规则列表 + 一组开关"一等公民化，并让项目独有的文件树
   承担大部分选区工作。
   **与 A+C 的谱系对应**：本设计 = A+C 的"原生重排版"——
   §2.2 快捷排除卡 = **A 的无损项**（目录/扩展名/表达式 + 文件大于 + 忽略大小写/标记文件/缓存）；
   §2.3 规则列表 = **C 的高级 pattern 入口升为一等公民**（不再折叠隐藏，直接承接 `**`/`!`/字符类原生能力）；
   §4 批次③的树标记排除 ⊘ = **A+C 没有的增量**（本项目有 browse 接口 + VirtualTree 才能做，
   生成精确锚定 pattern，绕开 Duplicati `-/dir/` 静默失效的坑）。
4. 树的浏览根引出部署形态问题：Docker 部署下"全文件系统"是容器内部垃圾；主机部署下
   "全文件系统"是真实可备份数据。owner 裁决：**自动判断，Docker 只显示 /sources，主机显示全部**。

## 1. restic 过滤能力实测基线（探针可复现）

探针：`.e2e/probe-restic-exclude2.sh` / `3b.sh` / `3c.sh`（restic 0.18.0）。

| 能力 | 语法 | 实测结论 |
|---|---|---|
| glob 排除 | `--exclude PATTERN` | Go `filepath.Match`；`*`/`?` 不跨 `/`；`[...]` 字符类 |
| 深度通配 | `**` | 有效且必须为完整路径组件：`**/lockdir` 排掉任意深度同名目录 |
| 负向 | `--exclude '!PATTERN'` | 有效但受 gitignore 限制：**父目录被排后无法捞回内部文件**；依赖规则出现顺序 |
| 大小阈值 | `--exclude-larger-than SIZE` | 有效（k/K/m/M/g/G/t/T） |
| 标记文件 | `--exclude-if-present NAME` | 官方参数（如 `.nobackup`） |
| 缓存目录 | `--exclude-caches` | 官方参数（CACHEDIR.TAG） |
| 忽略大小写 | `--iexclude PATTERN` | `--exclude` 的大小写不敏感孪生，独立 flag 列表 |
| 尾随 `/` | `-/dir/` | **被忽略** → `-/dir/` 锚定到文件系统根 → **静默失效**（必须转 `/sources/dir`） |
| 非法 pattern | `[abc` 等 | **Fatal exit 1，打死整个备份** |
| 花括号展开 | `{a,b}` | 不展开且**不报错**（静默空转） |
| 正则 | — | 不支持 |
| 声明式 include | — | 不存在；`--files-from(-verbatim/-raw)` 是**附加源清单**不是过滤器，且其 pattern 中 `**` 退化为单层 `*` |
| `--exclude-file` | `$VAR` | 会 `os.ExpandEnv` 展开环境变量 → **禁用该通道**，恒走 `--exclude` argv |
| 排除作用域 | — | **不作用于显式备份源根目录本身**，只过滤其内部 |

### 由基线推出的两条存量代码缺陷（随本方案必修）

1. `backend/app/exclusions.py` `normalize_user_excludes` **不校验 glob 语法**——用户填
   `[abc` 即可让整个备份 Fatal。必须加语法校验（后端 422 前置拦截）。
2. `!` 前缀走了「不以 `/` 开头 → 原样透传」分支，不会映射成 `!/sources/...` 前缀 →
   锚定文件系统根 → 静默失效。负向规则须先剥 `!` 再做前缀映射。

## 2. 原生过滤条件设计

### 2.1 形态总览（已实施定稿，A 裁决 owner 2026-10-24）

```
第②步 源数据
├ 左：文件树（双模式见 §3；挂载点快跳 chips + 挂载徽章 + ⊘ 树标记排除已落地）
└ 右：
  ① 路径卡（已选源，可编辑行——已落地，见 UI全量改造方案 v1.29）
  ② 排除卡（一张卡内三区块，**编号即优先级，③ 最高**）
     ├ ① 匹配规则（按顺序生效）：快捷生成（扩展名/名称包含）→ 有序规则列表
     ├ ② 独立开关（任一命中即排除）：文件大于 / 标记文件 / 跳过缓存
     └ ③ 内置排除集（强制生效，只读；A 裁决后排 --exclude 队尾，负向不可取消）
  ③ 固定提示条：排除不作用于已选源根目录本身
```

**A 裁决（owner 2026-10-24）——内置集真强制**：原实现内置集排 `--exclude` 队首，用户负向
规则可取消内置排除，与 UI「强制生效」承诺矛盾。裁决后五处装配点（job_runner 存量/批次②、
backup_tasks 预览 spec/存量、sources 预览 spec/存量）统一走单一函数
`exclude_spec.assemble_excludes(user, builtin)`——**用户 pattern 在前、内置集队尾**；
restic 后命中者赢 → 内置集真强制。UI 侧三区块按同一优先级重排（编号 ①②③）。

### 2.2 快捷排除卡（生成锚定 pattern，用户不接触语法）

| 控件 | 生成 |
|---|---|
| 扩展名 chips（`.tmp` `.log`） | `**/*.tmp`、`**/*.log` |
| 名称包含（单输入框） | `**/*X*`，tooltip 诚实标注「同名文件会一起排（restic 无仅目录谓词）」 |
| 文件大于 | `--exclude-larger-than`（如 `100M`） |
| 标记文件（预设 `.nobackup` / 自定义名，可多个） | `--exclude-if-present` |
| 跳过缓存目录 | `--exclude-caches` 开关 |

### 2.3 排除规则列表（高级）

每行 = `[! 负向开关] [glob 输入框] [生效预览: /sources/data/**/*.bak] [忽略大小写开关] [上移/下移] [删除]`。

- **规则顺序 = argv 顺序**（`!` 负向语义正确性的保证；展平顺序：quick 生成的 pattern 在前，
  rules 按列表序在后——保证负向总能取消快捷卡的宽规则）。
- **生效预览**是本设计灵魂：把 `/sources` 前缀映射结果直接展示，"静默失效"类坑在保存前暴露。
- 前端实时 glob 语法校验 + 后端 422 前置拦截（共用校验器口径）。

### 2.4 数据模型

```ts
interface ExcludeSpec {
  quick: {
    extensions: string[]          // → **/*.ext
    nameContains: string          // → **/*X*
    largerThan: string | null     // → --exclude-larger-than
    ifPresent: string[]           // → --exclude-if-present
    caches: boolean               // → --exclude-caches
  }
  rules: { pattern: string; negate: boolean; icase: boolean }[]  // 有序！
}
```

后端：`quick` 展平为锚定 pattern；`negate=false 且 icase=true` 的规则进 `--iexclude`，
其余（含全部负向）进 `--exclude`。**已探针钉死（2026-10-24，restic 0.18.0，`.e2e/probe-icase-negation.sh`）**：
`--iexclude "!X"` 在 `--iexclude` 族内生效且大小写不敏感（实测 `--iexclude "*.log"` + `--iexclude "!KEEP.LOG"` 成功捞回 `KEEP.LOG`）；
但**跨 flag 负向无效**——`--iexclude "*.log"` + `--exclude "!KEEP.LOG"` 与反向 `--exclude "*.LOG"` + `--iexclude "!*.log"` 两向实测均**不能**取消。
故 **`negate ∧ icase` 禁用**（后端 422 `VALIDATION_ERROR`；UI 负向行隐藏 icase 开关）；负向只能取消**同族**（`--exclude`）的正向。
实现见 `backend/app/services/exclude_spec.py`（`validate_glob` / `validate_size` / `flatten_exclude_spec`）。

## 3. 树双模式（部署形态自动检测）

### 3.1 检测规则

```
is_container = DEPLOY_MODE 显式指定 ? env 值
             : Path("/.dockerenv").exists()
             : (兜底) /proc/self/mountinfo 根分区为 overlay
effective_browse_root = is_container ? settings.sources_root(默认 /sources) : "/"
```

原则：**自动检测只决定默认值，不充当安全边界**；安全边界永远是 deny 清单 + 显式 env
覆盖（`DEPLOY_MODE=host|docker|auto`，默认 auto）。

### 3.2 单一事实源（防 UI/校验漂移）

`effective_browse_root` 在后端启动时算一次，经 bootstrap/settings API 下发前端；
`PathMapper`、源路径校验、排除规则前缀映射**全部改读同一值**。UI 允许选的路径与后端
接受写入的路径永不不一致（S2 argv 白名单的前置条件）。

### 3.3 两模式的树与 deny

| 模式 | 树根 | 数据端点 | deny/警示 |
|---|---|---|---|
| Docker | `/sources` | E05（现状不变） | 现状白名单；挂载点快跳列 `/sources` 下挂载 |
| 主机 | `/` | E33 `fs/browse` | `/proc` `/sys` `/dev` `/run`（E33 `_MOUNT_PREFIX_DENY` 现成）；**新增**：仓库自身存储位置（防备份递归）、应用 DB/密码文件目录（密码文件 E5 已挡，DB 目录要补） |

> **恢复链路同步派生（2026-10-25，owner 裁决 Q1=A）**：本节的「单一事实源」纪律已扩展到恢复——
> `restore_allowed_prefixes`（时间戳流：docker `/restore` / host `/`）与
> `inplace_restore_allowed_prefixes`（原位流，与备份源同源）一并按部署形态派生，
> `GET /api/system/runtime` 下发 `restore_root` / `inplace_root`；恢复树根与
> 「展示形态 → 容器形态」换算均据此前端零写死（详见 `UI全量改造方案.md` §4.9.8）。

边界情况：WSL/开发机检测为 host（树显示真实 `/mnt/d/...`，利于调试）；非 root 运行时
无权限目录 403，树内显示"无权限"即可。

### 3.4 挂载点快跳（两模式通用）

仓库页「浏览路径」弹窗已有完整实现（解析 `_mount_points()` fs.py:142、API `mounts`
fs.py:87-91、UI chips repo/index.vue:2126-2141）。搬运清单：

1. E05 `/api/sources` 响应补 `mounts`（复用 `_mount_points`，按 `sources_root` 前缀过滤）；
2. SourcesPicker 树顶加同一排 chips（根 + 各挂载点，点击跳转）；
3. 树节点挂载徽章：`FsItem.is_mountpoint` 字段已存在但**无前端消费方**——补 `VirtualTree`
   节点图标，零后端改动。
