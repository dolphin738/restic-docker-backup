# Web 版部署指南（2026-10-16 校准 · 适用于 v1.0.0 及以后镜像）

面向"拿到镜像直接部署"的运维路径。设计方案口径见 `Web版改造方案.md`（§3 路径与能力、§4 部署形态、
§6.1 鉴权），实现口径见 `架构设计文档.md`。

---

## 1. 前置条件

| 项 | 要求 |
| --- | --- |
| Docker | 20.10+（含 Compose v2） |
| 磁盘 | `/data`、`/cache/restic` 需持久化；缓存大小约为备份数据量的百分之一量级，请勿放 tmpfs |
| 端口 | 默认 `8000`（`PORT` 可覆盖） |
| 仓库 | 其一：S3 兼容（MinIO / COS / OSS / Wasabi…）、Backblaze B2、本地路径（挂 `/repo`） |
| 密码文件 | 宿主机生成，放 `./data/repos/default/password`（容器内 `/data/repos/default/password`，权限 600）；根目录可用 `PASSFILE_ROOT` 覆盖 |
| 页面 | **镜像已内置前端产物**（`/app/webroot`），8000 端口同时提供页面与 API，无需额外静态服务器 |
| 浏览器 | Chrome / Edge / Firefox **最近两个大版本**、Safari 最新版；**不支持 IE 及已停止安全更新的版本**（完整清单见 §11） |

> **仓库类型仅 s3 / b2 / 本地路径**（方案 §4.2）。rclone / sftp / REST Server **均未接入**
> （需求池 R-022，owner 2026-10-16 再确认维持暂缓）；Swift / Azure / GCS 明确不接入。

## 2. 部署

### 2.1 准备目录与密码文件

```bash
mkdir -p restic-web/{data/repos/default,cache,restore}
openssl rand -base64 48 > restic-web/data/repos/default/password
chmod 600 restic-web/data/repos/default/password
```

密码文件是**加密根密钥**：不可轮换、不入数据库、不出 API、永不入库（方案 §6）。
**丢失 = 历史备份永久不可解密**，请另行离线保管。

> **布局约定（架构 §13 E5）**：密码文件按**仓库维度**摆放——`<PASSFILE_ROOT>/<repo_id>/password`，
> 根目录默认 `/data/repos`（环境变量 `PASSFILE_ROOT` 可覆盖）。首次部署的 `default` 仓库即
> `/data/repos/default/password`（上面的 `mkdir`/`openssl` 就是为它准备的）。多仓库已落地
> （R-023）：每仓库一份、**互不共用**（restic `--password-file` 只提供单一密码值，
> 共用＝所有仓库同一密码，无法单库轮转）。
>
> **新建仓库的密码文件从哪来**（R-023 多仓库下最容易漏的一步）：两条路，任选其一——
> ① **UI（推荐，无需进宿主机）**：仓库页「设置仓库密码」→ 一键生成强随机密码或自行填写，
> 后端写入 `<repo_id>/password`（端点 E44，`POST /api/repos/{repo_id}/password`）。
> 生成的明文**只显示一次**，弹窗关闭后无法再查看，请当场存进密码管理器；
> ② **手动**：在宿主机挂载点 `data/repos/<repo_id>/password` 放好文件（`chmod 600`），无需重启容器。
> 已存在密码文件时 E44 会拒绝覆盖（422）——因为它同时是凭据加密的密钥源，覆盖会让仓库不可读、
> 已加密凭据全部失效。
>
> 仓库列表的「密码文件」列与状态卡会显示「已挂载 / 缺失」；**缺失时「初始化仓库」按钮置灰**，
> 因为此时任何仓库操作都会因 restic 读不到密码而失败（`exit=1`）。
>
> **逃生舱**：容器环境变量 `RESTIC_PASSWORD_FILE` 一旦显式设置，就**覆盖**上述布局
> （在 compose 的 `environment:` 里配，**无 UI 入口**）——仅在你自己管理密码文件路径时使用，
> 设了它之后 E5 的 per-repo 布局对该容器不再生效。
>
> 两个运维提醒：
> ① 密码文件在数据卷内，备份 `/data` 时**建议只拷 `data/db`**（不要把加密根密钥跟着一起外发）；
> ② 非 root 档部署，`entrypoint.sh` 会 chown 整个 `/data`，密码文件属主随之变为 `PUID:PGID`——
> 若之后在宿主机用 root 改过该文件，可能再次变成容器内不可读，改完确认权限仍为 600 且属主正确。
>
> **凭据加密（R-025，默认开）**：S3/B2 凭据、数据库密码、通知渠道令牌在写入数据库前加密
> （AES-256-GCM，密钥由上述密码文件经 HKDF 派生、不进入数据库）——数据库文件单独泄露不再等于
> 凭据泄露。系统设置页「凭据加密」开关可随时切换（存量凭据自动转换形态）。**代价：密码文件成为
> 单点**——丢失或被更换 ⇒ 已加密的凭据全部解不开（与仓库本身同源，报错明确、不静默）；
> 关闭开关后凭据以明文存放，请仅在对密码文件可用性有把握时保持开启。

### 2.2 compose 启动（推荐）

复制 `web版/docker/docker-compose.yml` 到部署目录，按需调整后：

```bash
docker compose up -d
docker compose logs -f restic-web     # 首启观察 entrypoint 属主处理
docker inspect --format '{{.State.Health.Status}}' restic-web   # 应变为 healthy
```

compose 中只保留"容器怎么跑"的事实（挂载 / 端口 / 用户 / 镜像）；
**业务配置（仓库、凭据、策略、时区）全部在 Web 界面完成**（方案 §4.1）。

> 部署模板**不含 `build:` 段**：只使用已发布的 `dolphin738/restic-web:<版本>-restic<restic版本>`。
> 需要自行构建镜像时用叠加文件（见 §2.5），不要把 `build:` 加回部署文件。

### 2.3 备份源挂载（A0 模式收敛后唯一形态）

2026-10-17 起运行模式收敛为**单一 `/sources` 形态**（原 host/sources 二选一与
`RESTIC_WEB_MODE`/`HOST_MOUNT_MODE` 已退役）：宿主机目录挂载到容器 `/sources`，
备份源在 UI 里勾选，增删零重启。

| 卷 | 说明 |
| --- | --- |
| `-v ${SOURCES_DIR:-./sources}:/sources:rw` | 备份源根；`SOURCES_DIR` 可指向任意宿主机目录 |
| `-v /restore:/restore` | 恢复目标（时间戳子目录落点） |

- `rw`（默认）：支持**原位恢复**（写回 `/sources` 内该快照备份过的路径，需 E20 覆盖预览与确认门）；
- `ro`：只能备份与浏览，恢复目标被限制为 `/restore`（界面给出置灰原因）。
- 切 `ro` 只改卷串尾部一处即可（`/sources:ro`）；无宿主机 `.env` 插值坑（`SOURCES_DIR`
  缺省即 compose 同目录 `./sources`）。

> **远端数据当备份源**（NFS/SMB/S3/B2/OneDrive…）：先在宿主机挂载（`rclone mount`
> 通吃 70+ 云，NFS/SMB 用系统挂载），再把挂载点映射进 `/sources`——restic 只认容器内
> 可见的目录树。对象存储当源有性能（海量小文件逐个 GET 慢、请求费）与一致性（VFS 缓存）
> 共性代价，适合中低频、大文件为主场景；「S3 → B2」这类云到云复制优先 `rclone copy`
> 端到端传输，不必经本机带宽。

#### 2.3.1 远端源挂载指引（A4）

**核心认知**：restic（及本应用）只能备份「容器内可见的目录树」——这与 Duplicati 一致
（Duplicati 也只认操作系统可见的路径，云源同样要先挂载）。因此「源」与「目的」解耦：
仓库（目的）可用任意 restic 后端（local/s3/b2/sftp/azure/gcs/rest/rclone），而**备份源
只能是一个挂在 `/sources` 下的本地目录树**。远端数据当源 = 在**宿主机**把它挂成普通目录，
再让 compose 把该目录映射进容器 `/sources`，UI 里即可像本地目录一样勾选。

**三种挂载路线**：

1. **NFS / SMB（最常见）**：宿主系统挂载（`mount -t nfs ...` / `mount -t cifs ...`），
   挂载点如 `/mnt/nfs-share`，compose 加 `-v /mnt/nfs-share:/sources/nfs-share:rw`。
2. **rclone mount（70+ 云通吃）**：覆盖 S3 / B2 / Azure / GCS / OneDrive / Google Drive /
   Dropbox / 自建 WebDAV 等。宿主执行 `rclone mount remote:bucket /mnt/onedrive --daemon`
   （或 systemd 托管），compose 同样映射进 `/sources/onedrive`。**容器免 FUSE 特权**——
   挂载动作只发生在宿主机，容器只看到一个普通目录。
3. **其它 FUSE / 块设备**：同上，宿主挂载后映射进 `/sources/<子目录>`。

**映射约定（推荐）**：为避免与本地源混用，远端挂载统一落到 `/sources/<remote-name>/` 子目录，
UI 里据此区分数据来源。compose 示例：

```yaml
volumes:
  - ${SOURCES_DIR:-./sources}:/sources:rw
  - /mnt/onedrive:/sources/onedrive:rw      # 远端挂载点映射进 /sources 子目录
  - /mnt/nfs-share:/sources/nfs-share:rw
```

**UI 怎么填（A4 新增）**：向导第 2 步「备份源」除原有的目录树点选外，新增
「**手动输入挂载路径**」入口——直接键入容器内可见的绝对路径（如 `/mnt/onedrive`、
`/srv/nfs-share`），无需逐层浏览。该路径经后端 PathMapper 还原为 `/sources/<path>`，
恒落在 `/sources` 白名单内；前端已拦截空值、`..` 穿越段与非绝对路径。

**对象存储当源的两类代价（诚实标注）**：

- **性能**：海量小文件场景，每次备份都要逐个对象 GET（含 list + 元数据），远慢于本地磁盘；
  且多数云按请求数计费，「小文件多」会放大请求费。适合**中低频、大文件为主**的源。
- **一致性**：rclone mount 默认带 VFS 缓存（ `--vfs-cache-mode` ），缓存未刷新时可能读到
  旧快照；大文件写入建议 `--vfs-cache-mode writes` 并预留缓存盘空间。若源在备份窗口内仍在
  高频写入，优先用 `rclone sync` 落地到本地盘再备份，或接受「最终一致」语义。

**云到云复制不绕本机**：若目标是「S3 → B2」这类异地副本，直接 `rclone copy` 端到端传输
（对象存储之间走各自带宽），不必先挂成本机源、再经 restic 备份，省去本机带宽与二次写入。

### 2.4 运行用户与属主

- 镜像内应用默认以 `1000:1000` 运行；`docker-compose.yml` 显式指定 `user: "0:0"`（root 档），
  以便原位恢复完整还原属主与权限。
- **root 档**：`entrypoint.sh` 自动 `chown` `/data`、`/cache/restic` 到 `PUID:PGID`（默认 `0:0`），无需手工处理。
- **非 root 档**：容器内无法 chown，须先在宿主机执行
  `chown -R 1000:1000 ./data ./cache`，否则容器**拒绝启动**并在日志中给出明确提示。

能力分层（方案 §3.3，A0 后按运行用户分档）：非 root 档下，无权读取的文件会被 restic **静默跳过**，
UI 展示 `skipped` 计数与明细（R-012），需要完整还原属主请切 root 档。

### 2.5 需要本地构建镜像时

部署模板刻意**不带 `build:` 段**：若 build 与 image 同文件，本地构建产物会被打上发布镜像的名字
`dolphin738/restic-web:1.0.0-restic0.19.1`，之后本机 `docker compose up` 跑的其实是本地自构建镜像
（可能含未提交改动），且与官方镜像无法分辨。

本地构建走叠加文件 `web版/docker/docker-compose.build.yml`（它把镜像名改为本地专用的
`restic-web:1.0.0-local`，从根上避免同名顶替）：

```bash
cd web版/docker
docker compose -f docker-compose.yml -f docker-compose.build.yml build
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build
```

构建上下文为 `web版/`，与 CI 的 `scripts/ci-docker.sh` 同源；等价裸命令：

```bash
docker build -f docker/Dockerfile --build-arg RESTIC_VERSION=0.19.1 ..
```

## 3. 首启引导与鉴权

1. 浏览器打开 `http://<宿主机IP>:8000` → 首启引导页**一次性展示随机管理密码**（`GET /api/auth/bootstrap`，免鉴权）。
2. 立即保存，并以它作为"旧密码"设置新密码（E28）。展示过一次后该端点返回 `410 BOOTSTRAP_SHOWN`，
   密码明文不入容器日志。
3. 改密完成前，除登录与 bootstrap 外的所有接口被 Bootstrap 门拦截——**无鉴权的 Web 端 = rw 全盘挂载裸奔**，
   这一步不可跳过。

登录后：会话为 HttpOnly cookie（`SameSite=Lax`，非安全上下文自动不置 `Secure`），
写操作额外校验 `Origin` 同源；登录失败递增锁定（429 `ACCOUNT_LOCKED` 带 `retry_after`）。

## 4. 初始化业务配置（界面内完成）

| 步骤 | 界面 | 后端 | 说明 |
| --- | --- | --- | --- |
| ① 配置仓库 | 仓库配置页 | E06/E07 配置读写、E29 连通性测试、E30 仓库状态 | 类型 s3 / b2 / sftp / azure / gcs / rest / rclone / 本地路径（本地路径需挂 `/repo` 卷，见 4.1；远端后端见 4.2）；凭据可在界面填（加密存储），也可用 compose env 覆盖（env 优先） |
| ② 选备份源 | 备份源页 | E05 目录浏览、E32 内置排除集（只读） | 内置排除集统一派生 `/sources` 前缀，UI 可追加、**不可删减** |
| ③ 首备预览 | 备份源页 | E31 `backup --dry-run` 扫描范围预览 | 伪文件系统目录（`/proc` `/sys` 等）会给出警告 |
| ④ 手动备份 | 手动备份页 | E12 触发任务、E15 SSE 进度、E16 取消 | 进度走 SSE，`Last-Event-ID` 断点续传，刷新页面可续 |
| ⑤ 快照浏览 | 快照浏览页 | E17 快照列表、E18 文件树 | 分页 + 懒加载；路径已映射为宿主机原路径语义 |
| ⑥ 恢复 | 恢复向导页 | E19 恢复（默认时间戳子目录 / 原位恢复） | 默认 `/restore/<源目录名>-<时间戳>/...`，天然不覆盖；**原位恢复**需 `/sources` **rw 档**挂载且目标落在该快照备份路径内，经 E20 覆盖预览与单次确认门后执行（A7 起对齐 Duplicati，见 §10） |

### 4.1 本地路径仓库的额外三步（对象存储可跳过）

1. **挂载并填容器路径**：compose 中启用 `- <宿主机目录>:/repo`（默认整行注释），
   UI 仓库地址填 `/repo` 或 `/repo/<子目录>`。restic 在容器内执行，**只认容器路径**——
   填宿主机真实路径（如 `/mnt/backup/restic-repo`）必然报「仓库不存在或未初始化」。
   类型由地址前缀推导（`s3:`/`b2:`/`sftp:`/`azure:`/`gs:`/`rest:`/`rclone:` → 对应类型，
   其余→local；注意 gcs 的 restic 前缀是 `gs:` 不是 `gcs:`），代码不校验"必须以 /repo 开头"，填错只会在跑任务时炸。
2. **先跑一次 init**：保存地址后状态卡仍会显示「未连接」（仓库还没初始化）——
   点状态卡中的**「初始化仓库」**按钮（三步确认门，动作入审计）执行一次 `init`。
   自动初始化由行为开关 `AUTO_INIT` 控制（**缺省关**，R-017 已交付）。
3. **属主与摆放位置**：root 档下 `entrypoint.sh` 只 chown `/data` 与 `/cache`，**不处理 `/repo`**；
   非 root 档部署需自行 `chown 1000:1000 <宿主机仓库目录>`。
   另外仓库目录**不要落在会被勾选为备份源的位置**（备份源白名单 `/sources`）：
   若把仓库放在 `/sources/...` 下又勾成备份源，就成了"备份自己"，仓库会自我膨胀；
   仓库也不应与备份源共处同一块物理盘（盘坏则数据与备份一起没）。

> **默认恢复路径零覆盖**（时间戳子目录），这是防误覆盖设计而非功能缺失——方案 §3.4。
> **原位恢复**已随 R-015 交付，A0 后需 `/sources` **rw 档**挂载且目标落在该快照备份路径内；
> 不满足条件时入口置灰并给出原因（详见 §10）。

### 4.2 远端仓库后端（A1：sftp / Azure / GCS / REST / rclone）

除本地路径与 s3/b2 外，仓库地址可直接使用 restic 0.19.1 的原生后端前缀
（保存时按前缀做语法校验，非法形态 **422 拒绝**，不会落库）：

| 类型 | 地址形态 | 凭据 | 镜像依赖 |
| --- | --- | --- | --- |
| SFTP | `sftp:user@host:/srv/repo` 或 `sftp://user@host[:端口]/目录` | **无密码**：restic 经系统 ssh 免密登录（见下） | openssh-client（已含） |
| Azure Blob | `azure:容器名:/前缀` | 界面凭据或 env（见下方 env 表） | — |
| Google Cloud Storage | `gs:桶名:/前缀`（restic 前缀是 `gs:`，**不是** `gcs:`） | 界面凭据或 env（见下方 env 表） | — |
| REST 服务器 | `rest:https://host:8000/` | **禁止内嵌 `user:pass@`**（密码会明文落库且令 env 凭据失效）；走凭据字段 | — |
| rclone（万能后端） | `rclone:远端名:路径` | conf 宿主机托管（见下），凭据零落库 | rclone（已含） |

**rclone 万能后端**（一个类型覆盖 OneDrive/Google Drive/S3/B2/WebDAV 等 70+ 云，
对齐 Duplicati 的云端全家桶）：restic 对 rclone 仓库**按需拉起**
`rclone serve restic --stdio` 子进程（命令结束即退出，不常驻、不进事件循环）。
配置三步：

1. **宿主机添加远端**：`rclone config`（OneDrive/Google Drive 等 OAuth 型远端会在
   浏览器完成授权，token 写入 conf）；
2. **挂载 conf 进容器**：compose 取消 `./rclone/rclone.conf:/etc/rclone/rclone.conf:rw`
   一行的注释，并**先创建空文件**（`touch ./rclone/rclone.conf`——Docker 对不存在的
   bind 源会建**目录**顶替，rclone 将读不到 conf，状态卡会显示"未检测到配置文件"）。
   **必须 `:rw`**：网盘 OAuth token 过期时 rclone 回写 conf，只读挂载 = 授权静默失效；
3. **填地址**：UI 仓库地址填 `rclone:<远端名>:<路径>`（保存时校验远端在
   `rclone listremotes` 清单内，不在册 422 并列出可用远端）。状态卡/地址旁会同步
   显示可用远端清单。

UI 对 conf **只读探测**（`rclone listremotes`）：不生成、不编辑、不展示凭据——
conf 内 OAuth token 永不进 API；conf 加密口令（`RCLONE_CONFIG_PASS`）可经 env 或
界面凭据键 `rclone_config_pass` 提供（加密存储）。

**SFTP 免密登录**：restic 的 sftp 后端经系统 `ssh` 子进程（`location.NoPassword`，
URL 内密码会被当作用户名一部分**静默误解**——保存时直接 422 拒绝）。二选一：

- **私钥挂载（推荐）**：compose 取消 `./ssh/id_ed25519:/root/.ssh/id_ed25519:ro` 与
  `./ssh/known_hosts:/root/.ssh/known_hosts:ro` 两行注释。私钥须 `0600` 且属主匹配
  运行用户（root 档 `root:root`；nonRoot 档 `1000:1000` 并改挂 `/home/backup/.ssh`）；
  known_hosts 预先在宿主机生成（`ssh-keyscan <host> >> known_hosts`）——首次连接的
  host key 确认在非交互环境下会直接失败；
- **ssh-agent**：把 agent socket 挂载进容器（如
  `- /run/user/1000/ssh-agent.sock:/ssh-agent`），并在界面凭据字段填
  `SSH_AUTH_SOCK`（配置键 `ssh_auth_sock`）。

**凭据 env 覆盖表**（compose `environment`；env 优先于界面值，且只覆盖 **default**
仓库；界面填写的凭据一律加密存储，R-025）：

| 后端 | 环境变量 |
| --- | --- |
| Azure | `AZURE_ACCOUNT_NAME` / `AZURE_ACCOUNT_KEY` / `AZURE_ACCOUNT_SAS` / `AZURE_ENDPOINT_SUFFIX` |
| GCS | `GOOGLE_PROJECT_ID` / `GOOGLE_APPLICATION_CREDENTIALS` / `GOOGLE_ACCESS_TOKEN` |
| REST | `RESTIC_REST_USERNAME` / `RESTIC_REST_PASSWORD` |
| rclone | `RCLONE_CONFIG_PASS`（conf 加密口令；`RCLONE_CONFIG` 由 compose 固定为 `/etc/rclone/rclone.conf`） |

> SAS token（`AZURE_ACCOUNT_SAS`）与主权云端点（`AZURE_ENDPOINT_SUFFIX`，如 Azure 中国）
> 目前仅 env 通道提供，界面字段后续随类型选择卡（批次 A5）补齐。

## 5. 反向代理与 TLS

后端已为 SSE 下发 `Cache-Control: no-cache` 与 `X-Accel-Buffering: no`（`app/routers/jobs.py`），
反代侧仍需关闭缓冲并放宽读超时。

### 5.1 Nginx 示例

```nginx
location / {
    proxy_pass http://127.0.0.1:8000;   # 应用监听地址（同机部署走 127.0.0.1，容器场景写服务名:8000）
    proxy_http_version 1.1;             # HTTP/1.1：SSE 长连接必需（HTTP/1.0 无分块持久连接）
    proxy_set_header Host $host;        # 透传原始 Host：应用按它拼重定向与 Cookie 域
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;   # 保留客户端真实 IP（登录限流按 IP 计）
    proxy_set_header X-Forwarded-Proto $scheme;                    # 告知应用外层是 https（配合 FORCE_HTTPS/trust_proxy）

    proxy_buffering off;                # SSE 必须：关掉响应缓冲，否则进度事件被攒着一起发
    proxy_read_timeout 3600s;           # 长任务（备份/check/恢复）不被反代切断，按实际耗时调大
    # 反代 HTTPS 时另需：proxy_set_header X-Forwarded-Host $host;
}
```

### 5.2 Caddy 示例（自动 HTTPS，推荐）

Caddy 的自动 HTTPS 是一整条龙：**首次申请 → 到期前自动续期**，都不需要写额外指令。
下面这份配置里你看不到任何"续期"字样，因为它默认就开着：

```caddyfile
# 站点地址写域名 = 自动 HTTPS 的开关；不写域名（如 :80 / localhost）就不会去申请证书
backup.example.com {
    encode gzip                         # 压缩静态产物与 API 响应（SSE 流本身不压缩，避免缓冲语义变化）

    reverse_proxy restic-web:8000 {
        # SSE 必须：关掉响应缓冲，否则进度事件会被攒着一起发，前端表现为"进度卡住后突然跳完"
        flush_interval -1
        # 长任务不被反代切断：备份/check/恢复可能跑几十分钟到数小时，按实际耗时调大
        transport http {
            read_timeout 3600s
        }
    }

    log {
        output stdout                   # 走容器标准输出，交给 Docker json-file 轮转（见 §7）
        format console
    }
}
```

compose 侧要点（应用容器不发布端口到宿主机，只与 Caddy 同网络）：

```yaml
services:
  restic-web:
    # 去掉 ports: 映射——应用只在容器网络内可达，外部一律经 Caddy
    # （仍保留 image/volumes/environment 等原有配置，此处只列反代相关项）
    expose:
      - "8000"            # 仅对同网络容器暴露，不映射到宿主机
    networks: [web]

  caddy:
    image: caddy:2
    ports:
      - "80:80"           # ACME HTTP-01 挑战要用 80（首次申请与后续续期都要），不可省
      - "443:443"         # 对外 HTTPS
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data      # 【关键】证书私钥 + ACME 账户状态：不持久化会反复申请，易撞 Let's Encrypt 限流
      - caddy_config:/config  # 自动 HTTPS 的最后一份配置快照（caddy reload 用）
    networks: [web]

volumes:
  caddy_data:
  caddy_config:

networks:
  web:
```

> **前置条件**：① 域名已解析到本机；② 80/443 入站放行（80 是挑战端口，续期也要用）。
> 内网无域名、或由企业 CA 统一签发（**不自动申请/续期**）的场景见 §5.3。

### 5.3 Caddy 不自动申请/续期证书：自带证书（手动托管）

适用：内网无公网域名、ACME 不可达、企业 CA 统一签发、或由 acme.sh / certbot 在宿主机统一签发后
交给 Caddy 加载。此时 Caddy **只负责加载你给的证书**，不申请、不续期。

```caddyfile
# 全局选项：彻底关掉自动 HTTPS（不再申请证书、不再做 HTTP→HTTPS 跳转、不再监听 80 做挑战）
{
    auto_https off
}

backup.example.com {
    # 指定证书与私钥：Caddy 直接加载这两个文件
    #  - fullchain.pem：站点证书 + 中间 CA 证书（顺序：叶子在前，中间在后）
    #  - privkey.pem ：私钥，权限 600、属主需为容器内 caddy 用户可读
    tls /etc/certs/fullchain.pem /etc/certs/privkey.pem

    encode gzip

    reverse_proxy restic-web:8000 {
        flush_interval -1               # SSE 必须（同 §5.2）
        transport http {
            read_timeout 3600s          # 长任务不被切断（同 §5.2）
        }
    }

    log {
        output stdout
        format console
    }
}
```

compose 侧：证书以只读方式挂载，80 端口**不再需要**（没有 ACME 挑战）：

```yaml
services:
  caddy:
    image: caddy:2
    ports:
      # 无 ACME 挑战，只映射 443 即可；如需保留 http→https 跳转（auto_https off 后不会自动跳），
      # 再单独写一个 :80 站点块做 redir，或干脆不映射 80
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - ./certs:/etc/certs:ro           # fullchain.pem / privkey.pem 所在目录，只读挂载
      # 注意：此模式不需要 caddy_data 卷（没有要持久化的 ACME 状态）
    networks: [web]

networks:
  web:
```

**续期由你负责**（Caddy 不会自动做）：证书在宿主机更新后，让容器重新加载配置即可：

```bash
# 宿主机上用 acme.sh / certbot 续期，把新证书写到 ./certs/ 后：
docker compose exec -w /etc/caddy caddy caddy reload --config /etc/caddy/Caddyfile
# 若 reload 不可用（镜像裁剪），退一步重启容器：docker compose restart caddy
```

| 对比 | §5.2 自动 HTTPS | §5.3 自带证书 |
| --- | --- | --- |
| 证书从哪来 | Caddy 自动申请（Let's Encrypt） | 你提供（企业 CA / acme.sh / certbot） |
| 续期 | Caddy 自动（到期前自动续） | **手动**：外部续期 + `caddy reload` |
| 80 端口 | 必需（ACME HTTP-01 挑战） | 不需要（可只开 443） |
| 需持久化 `caddy_data` | 是（证书与 ACME 账户） | 否（无 ACME 状态） |
| 过期后果 | 一般无感（自动续） | 证书过期 = 站点直接不可访问，需监控到期日 |
| 内网无域名 | 不适用 | 适用（用内网 CA 签发的证书即可） |

> 运维提醒：把证书到期日纳入监控（如 `openssl x509 -enddate -noout -in certs/fullchain.pem`），
> 并在续期脚本里带上 `caddy reload`——只换文件不 reload，进程里仍是旧证书。

### 5.4 通用要点

- 心跳：默认 15s（`SSE_HEARTBEAT_SECONDS`）。若反代 idle timeout 明显小于 15s，需**下调心跳间隔**，
  否则反代会先于心跳断开长连接，前端误判断流并反复重连。
- TLS：三选一 —— ① 反代终结 + **自动 HTTPS**（推荐，Caddy §5.2）；
  ② 反代终结 + **自带证书**（内网/企业 CA，Caddy §5.3）；
  ③ 界面配置 `server.tls_cert` / `server.tls_key`，应用以 uvicorn ssl 参数**直接起 HTTPS**（无自动签发续期，证书挂载进容器、更新后需重启应用）。
  启用③后容器内置 HEALTHCHECK 需改为 https 或改由反代侧探测（busybox `wget` 无 TLS 支持，见 Dockerfile 注释）。
- 反代后的两项配套：登录限流按客户端 IP 计，需正确透传 `X-Forwarded-For`；
  应用侧 `FORCE_HTTPS` / `trust_proxy` 决定是否信任 `X-Forwarded-Proto`（反代终结场景置 `trust_proxy=1`）。

## 6. 升级与回滚

三条版本线彼此独立，升级方式见 `依赖升级指南.md`：

```bash
# 应用升级：改镜像 tag（compose 的 image:）后重建
docker compose pull && docker compose up -d

# restic 升级：改 Dockerfile 的 ARG RESTIC_VERSION 后重新构建镜像（随镜像原子发布）
# 基础镜像升级：改 Dockerfile 的 FROM python:3.13-alpine3.24
```

> 本地自构建的场景，版本号需三处同步：`docker-compose.yml` 的 `image:`（应用版本）、
> `docker-compose.build.yml` 的 `image:` 与 `args.RESTIC_VERSION`、
> `docker/Dockerfile` 的 `ARG RESTIC_VERSION`（restic 版本）。

- **回滚**：把 `image:` 改回上一个双版本标签（如 `...:1.0.0-restic0.19.1`）重建即可；
  `/data` 内的 SQLite 由 `user_version` 幂等迁移器管理，**只升不降**，降级镜像遇到高版本库会报错，
  此时应恢复升级前的 `/data` 备份。
- **restic 大版本升级后**仓库格式可能变更，务必先确认目标版本能读取既有仓库。

## 7. 备份与灾难恢复（元数据安全）

| 数据 | 位置 | 丢失后果 | 建议 |
| --- | --- | --- | --- |
| 仓库密码 | `data/repos/default/password`（容器内 `/data/repos/default/password`） | 备份永久不可解密 | 离线多地保管；备份 `/data` 时**只拷 `data/db`**，不要把密码文件一起外发 |
| SQLite + 任务日志 + dump | `/data` | 任务历史/配置丢失（快照数据仍在仓库内） | 定期拷贝 `data/db` |
| restic 缓存 | `/cache/restic` | 仅变慢，不丢数据（重建后首次全量重扫） | 持久化即可 |

容器日志建议交给 Docker 轮转（方案 §8.1）：

```yaml
logging:
  driver: json-file
  options:
    max-size: "10m"
    max-file: "3"
```

### 7.1 仓库自愈：RecreateDatabase 等价操作（批次 C，B1/B2/B3）

Duplicati 的「RecreateDatabase（本地库损坏时从远端卷重建）」在 restic 语义下**不需要专门操作**：
restic 没有独立本地数据库，`/cache/restic` 只是加速缓存，**删掉即自动重建**（界面「缓存维护」
一键清空，代价仅首次操作全量重扫变慢，不丢任何数据）。真正需要对仓库动手的只有三类场景：

| 场景 | 判断依据 | 处置 |
| --- | --- | --- |
| 缓存损坏 / 占用异常 | 操作报缓存 IO 错误、`/cache` 异常膨胀 | 「缓存维护」清空缓存（E25）——**永远先试这个**，零风险 |
| 索引 / 卷结构损坏 | check 报结构性错误（`suggest_repair_index`）或恢复失败 | 「仓库配置 → 修复仓库」（B1）：`repair index` 重建索引 / `repair packs` 修损坏卷 |
| 中断备份的孤儿数据 | 备份被强杀后快照数对不上、check 提示索引缺失 | 触发 `recover`（B3）扫描仓库找回未入索引的快照数据 |

三类自愈动作均改写仓库元数据或需要全量重扫，**执行期间请勿并发读写仓库**；
repair / recover 走三步确认门（关键词 `REPAIR`），且各留审计（`repair.run` / `recover.run`）。

没有界面时的 API 触发方式（`X-Repo-Id` 指定目标仓库）：

```bash
# 修复索引（B1，最常用；packs 换成 {"repair_target":"packs"} 即修卷）
curl -X POST http://localhost:8000/api/jobs \
  -H "Content-Type: application/json" -b "session=<cookie>" \
  -d '{"type":"repair","params":{"repair_target":"index"}}'

# 找回未快照数据（B3，无参数）
curl -X POST http://localhost:8000/api/jobs \
  -H "Content-Type: application/json" -b "session=<cookie>" \
  -d '{"type":"recover"}'
```

损坏检测（B2）：任务历史的 check 详情抽屉（E22）展示 blob 级损坏 pack 清单 +
「一键修复索引」建议链；**文件级损坏映射为受限项**——restic 无原生的文件级损坏定位命令，
如需精确定位受影响文件，请以受影响快照为范围做恢复演练（恢复报错即该快照含损坏数据）。

### 7.2 多目的地镜像、手动搬家与密钥轮换（批次 D，C1–C4）

**任务级多目的地镜像（C4）**：任务向导「存储目标」步骤可为任务选择最多 3 个镜像仓库；
主仓库备份**成功后**，系统自动把本次新快照**增量复制**（restic copy，只传新快照）到各镜像仓。
运维须知：

- **首copy 必传全量**：镜像仓第一次收到某任务的数据时走全量网络传输（后续只传增量），
  与首次备份等量级——请预估目的端带宽与存储；
- **失败隔离**：镜像阶段失败**不改变主目的地任务状态**（主仓数据已落好，标失败属谎报），
  失败原因看任务日志 `[copy]` 行与审计（`copy.run`）；下一次备份成功后会**自动补齐**落下的
  快照（restic copy 按任务 tag 增量比对，自愈，无需手工干预）；
- **前置校验双保险**：镜像仓未配置地址/密码会在保存任务时被 422 拦截；运行期若仓库配置
  中途被删则优雅跳过并留审计（`skipped`），绝不静默。

**手动搬家 / 异地副本（无任务场景）**：「仓库配置 → 状态卡 → 复制快照到…」把当前仓库
全部快照增量复制到目标仓库（`POST /api/copy`，超时 3600s；中断后重跑自动续传）。
典型用途：本地盘搬去 S3 不想从头全量备份、给现有仓库建一份异地副本。

**密钥轮换（C4，Duplicati 无等价能力）**：「仓库配置 → 状态卡 → 密钥轮换」在**旧密码仍
有效**时把仓库密码改为新密码（`POST /api/repos/rotate-key`，restic key passwd）：
成功后旧密码立即作废、仓库口令文件同步重写（新密码不回显、不落审计明文）。适用场景：
密码疑似泄露、定期轮换。注意：轮换后若你有**其它工具用旧密码访问该仓库**（如脚本直跑
restic），须同步改用新密码。

**失败自动重试（C3）**：任务「失败重试次数」（0–5，默认 2）只作用于**调度触发**的备份
失败（指数退避）；手动「立即运行」不重试。重试仍失败才计终态失败并触发通知。

**SMTP 邮件通知（C2）**：「通知设置」页新增邮件渠道（SMTP host/port/账号/授权码/发件人/
收件人/加密方式）。容器需**能出站访问 SMTP 端口**（默认 587 STARTTLS；465 TLS；25 明文
不推荐）——受限网络环境请放行对应出站规则。授权码与密码三态语义同其它敏感字段：
保存后不回显、留空不变、点「清除」后保存即删除。

**配置迁移（批次 E）**：「系统设置」页「配置迁移」卡。**导出**：设一个导出口令
（≥10 位），生成 JSON 文件（仓库清单 + 任务 + 通知配置 + 凭据——凭据段经该口令
PBKDF2+AES-GCM 加密，文件泄漏不含明文凭据；备份数据本身不在导出范围）。**导入**：
选文件 + 输入该文件的导出口令；同 id 仓库 / 同仓同名任务**默认跳过**并在报告里逐项
列明原因；勾选「覆盖已存在项」（需输入 IMPORT 确认）则以文件内容整体替换，不可逆。
导入后请到仓库页确认各仓凭据可用（目标机侧密码文件仍需与导出方仓库密码一致）。
同一份文件重复导入结果一致（幂等），可用于迁移后的校验。

## 8. 日志格式与级别

容器日志统一为**一行一事件、首字段时间戳**：

```
2026-10-12 04:30:27+0800 INFO    uvicorn.error | Uvicorn running on http://0.0.0.0:8000
2026-10-12 04:30:31+0800 INFO    uvicorn.access | 127.0.0.1:49806 - "GET /api/health HTTP/1.1" 200 OK
2026-10-12 04:31:02+0800 INFO    restic-web | 未配置 server.tls_cert/tls_key，以纯 HTTP 启动
```

- 格式：`%(asctime)s %(levelname)-7s %(name)s | %(message)s`，`datefmt=%Y-%m-%d %H:%M:%S%z`。
- **时间戳带 `%z` 偏移**，取容器 `TZ`（compose 模板已设 `Asia/Shanghai`，镜像内置默认 UTC）。
  看日志时别把 `+0800` 当 UTC，也别把 UTC 部署的时间直接对本地时钟。
- `uvicorn.access` 是访问日志（每条 HTTP 请求一行，含 30s 一次的 `/api/health` 健康探测）；
  `uvicorn.error` 是服务自身事件；`restic-web` 是应用日志（启动、鉴权、任务编排）。
- 级别：`LOG_LEVEL` 环境变量（默认 `INFO`，可选 `DEBUG/WARNING/ERROR`），compose 模板已显式写出。
  DEBUG 会打印 restic argv 级别细节，排查完请调回 INFO。
- 轮转由 Docker 负责（见 §7 的 `json-file` `max-size/max-file`），应用侧不写日志文件——
  SQLite 在 `/data`，日志不会占用数据卷。

## 8.5 Prometheus 指标（R-024）

指标端点：`GET /api/metrics`（Prometheus exposition format 0.0.4），**pull 模型**——
抓取时从数据库即时聚合（无进程内计数器，重启不丢计数）。

**鉴权二选一**（owner 2026-10-16 裁决）：

1. **Bearer 令牌**（推荐给 scraper）：系统设置 →「Prometheus 指标」页设置抓取令牌
   （库内只存 SHA-256 哈希，设置后不可读，遗失请重新生成）；
2. **已登录会话**：浏览器登录状态下直接访问（适合临时查看）。

```yaml
# prometheus.yml 片段
scrape_configs:
  - job_name: restic-web
    metrics_path: /api/metrics
    authorization:
      credentials: <抓取令牌>   # 与界面设置的令牌一致
    static_configs:
      - targets: ['restic-web:8000']   # 或反代后的外部地址
```

主要指标：`restic_web_backup_jobs_total{status}`（按终态计数）、
`restic_web_backup_success_ratio`（成功率，无历史为 -1）、
`restic_web_backup_last_success_timestamp_seconds`（距上次成功备份的秒数，告警友好）、
`restic_web_backup_last_skipped_files`（R-012 跳过数）、`restic_web_jobs_active`。
**备份成功率报表**（按天、按配置时区）见左侧导航「报表」页。

## 9. 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 日志行没有时间（只有 `INFO:     Uvicorn running on ...`） | 拉的是 v1.0.0 之前的镜像或本地旧构建：时间戳格式自 v1.0.0 起内置（见 §8），重建/重新拉取即可 |
| 打开首页显示 `{"code":"NOT_FOUND","message":"Not Found"}` | 镜像不含前端产物：v1.0.0 起的镜像内置 SPA（`/app/webroot`），请拉取/重建该版本及以后的镜像。自建镜像时确认 Dockerfile 的 `frontend-build` 阶段成功；也可把 dist 挂进容器并用 `STATIC_DIR` 指向它（目录内须有 `index.html`） |
| 容器反复退出，日志提示目录不可写 | 非 root 档未 chown：宿主机执行 `chown -R 1000:1000 ./data ./cache` |
| `docker inspect` 健康状态 `unhealthy` | `GET /api/health` 探测进程与 SQLite；查 `docker logs` 中的建库错误（多为属主/权限） |
| 页面进度条不动或反复重连 | 反代未关缓冲或 idle timeout < 心跳：按 §5 配置，或下调 `SSE_HEARTBEAT_SECONDS` |
| 备份成功但文件数偏少 | 非 root 档权限不足导致静默 skipped：查任务日志中的 skipped 明细，或切 root 档 |
| 恢复找不到"原位置"选项 | 原位恢复需 `/sources` **rw 档**挂载，且目标须落在该快照的备份路径内：ro 档下入口按设计置灰（§10） |
| 找不到"策略"页面 | 策略职能已由**备份任务**全量承担（Q1 选删）：cron / keep_* / 限速等字段在任务向导里配置，无独立策略页 |
| `SQLITE_BUSY` | 调大 `DB_BUSY_TIMEOUT_MS`（默认 5000） |
| 时区不对 | 设 `TZ=Asia/Shanghai`（镜像默认 UTC） |

## 10. 当前版本边界（2026-10-17 校准，A0 模式收敛）

> 本节为**当前实现**的能力边界，早期版本的「P1 边界」条目已全部交付，不再适用。

- **运行形态（A0，2026-10-17）**：只认容器内可见目录树——宿主机目录（含 NFS/SMB/rclone mount
  挂载点）映射到 `/sources` 即备份源；原 host 整盘模式已退役（`RESTIC_WEB_MODE`/`HOST_MOUNT_MODE`
  作废，存量 `/host/*` 快照需改为自定义目标恢复）。
- **恢复**：默认恢复到 `/restore/<源目录名>-<时间戳>/...`（零覆盖）；**原位恢复已开放**，需
  `/sources` **rw 档**挂载，且目标须落在该快照的备份路径内（ro 档下入口置灰）。
  恢复向导**原位置为默认选项** + 覆盖勾选（默认不勾 = `--overwrite=never` 跳过已存在文件；
  勾选 = `always` 覆盖），单次确认门执行（A7 对齐 Duplicati；注意 Duplicati 不勾覆盖时是
  「冲突改名另存」，restic 无等价能力，本项目取最近似 never）。
- **仓库类型**：s3 / b2 / **sftp / azure / gcs / rest / rclone（A1，2026-10-17）** / 本地路径。
  rclone 为万能后端（按需子进程，conf 宿主机挂载、凭据零落库，见 §4.2）；sftp 免密登录
  （私钥挂载）；azure/gcs/rest 凭据走界面（加密）或 env。保存时按前缀严格校验（422）。
- **仓库数量**：多仓库已支持（R-023，P3-C 2026-10-16）——仓库管理页可新建/删除/切换，
  初始恒有 `default` 一行（密码文件 `/data/repos/default/password`）；新仓库的密码文件按
  `<PASSFILE_ROOT>/<repo_id>/password` 摆放，**可在仓库页「设置仓库密码」一键生成或自填**
  （E44，无需进宿主机），也可手动放置——缺失时「初始化仓库」按钮会置灰。
  仓库类型见上（s3/b2/sftp/azure/gcs/rest/rclone/本地路径；rclone/sftp 等远端后端见 §4.2）。
- **调度器**：已交付（per-task cron，含启动补跑）；cron 只收 **5 字段**，且日/星期同时受限时取 **AND**
  而非标准 Vixie cron 的 OR——填这两项时注意实际触发频率会低于预期。
- **限速**：`--limit-upload/--limit-download`（KiB/s，0=不限）已接入任务字段。
- **通知 / dump / 缓存维护 / 审计页**：均已交付。

## 11. 浏览器支持清单

按 PRD §6 兼容性（Q8 裁决）：**只支持仍在安全更新期内的现代浏览器**。

| 浏览器 | 支持范围 |
| --- | --- |
| Chrome（含 Chromium 内核） | **最近两个大版本** |
| Microsoft Edge | **最近两个大版本** |
| Firefox | **最近两个大版本** |
| Safari | **最新版**（macOS 大版本绑定，无法独立升版） |

**明确不支持**：Internet Explorer（含 IE11）及**任何已停止安全更新**的浏览器版本。
页面不做降级适配，旧浏览器可能出现白屏、样式错乱或 SSE 进度不刷新。

硬性能力依赖（缺一即不可用）：

1. **`EventSource`（SSE）**——备份/恢复/check 的实时进度全靠它，且需支持 `Last-Event-ID` 重连续传；
2. **CSS 虚拟滚动**相关布局能力——快照列表、任务卡片为虚拟列表，行高由 CSS 固定；
3. 现代 JS/CSS 语法（Vite 构建目标）——旧引擎解析即失败，无 polyfill 兜底。

> 反代场景另需浏览器侧不被中间设备缓冲 SSE，见 §5。
