# 依赖升级指南

> 适用：restic-docker-backup Web 版（`web版/`）。  
> 原则：**锁是保证"可重复"，升级是"显式动作"**——升级永远由人发起、测试把关、一次提交生效；CI 永远不自己追最新。

## 一、三条独立的版本线

| 版本线 | 锁定位置 | 升级动作 | 相互影响 |
|---|---|---|---|
| **Python 依赖** | `web版/backend/uv.lock`（约束在 `pyproject.toml`） | `uv lock --upgrade` 系列（见下） | 无 |
| **restic 版本** | `web版/docker/Dockerfile` 的 `ARG RESTIC_VERSION=0.19.1` | 改这一个字符串重新构建 | 无 |
| **基础镜像** | 同 Dockerfile 的 `FROM python:3.13-alpine3.24`（锁定 Alpine 小版本） | 改 FROM tag 重新构建 | 无 |

三条线互不干扰，各自都是"改一行/跑一条命令 → 测试 → 提交"的显式动作。

## 二、Python 依赖：升级工作流（uv）

### 1. 日常（什么都不做）

CI 用 `uv sync --frozen` 安装 `uv.lock` 里的**精确版本**——今天的构建和三个月后的构建产出完全一致。

### 2. 全量升级（建议每季度或每月一次）

```bash
cd web版/backend
uv lock --upgrade          # 在 pyproject 约束范围内全部升到最新，重写 uv.lock
uv sync --frozen --extra dev
uv run --no-sync pytest -q # 本地全量回归（当前 117 条）
```

建议开 `feat/upgrade-deps` 分支操作，绿了再合并——一次性集中处理不兼容变更。

### 3. 单包升级（如安全通告）

```bash
uv lock --upgrade-package fastapi   # 只动这一个包，其他纹丝不动
uv sync --frozen --extra dev && uv run --no-sync pytest -q
```

### 4. 跨约束升级（需要新的大版本特性）

先改 `pyproject.toml` 的版本约束（如 `fastapi>=0.150`），再 `uv lock && uv sync --frozen --extra dev`，测试后提交（`pyproject.toml` 与 `uv.lock` **必须同一提交**）。

### 5. 回滚

`git revert` 那个升级提交即可——锁文件回滚 = 环境精确回滚，没有半升不升的状态。

## 三、restic / 基础镜像：升级工作流

```bash
# restic 升级（方案原话："升级 = 改一个 tag 字符串 + CI 重建"）
#   编辑 web版/docker/Dockerfile：ARG RESTIC_VERSION=0.19.1 → 0.20.x
# 基础镜像升级（Alpine 小版本 / Python 补丁版）：
#   编辑 FROM python:3.13-alpine3.24 → 新 tag
```

提交后手动触发流水线（分支详情页「构建并推送镜像」）验证构建 + 测试。

## 四、发布（出双版本镜像标签）

```bash
git tag v1.x.y <要发布的commit>
git push origin v1.x.y
```

然后到 CNB 分支详情页点「构建并推送镜像」——脚本检测到 HEAD 恰好是 tag 目标时，自动追加双版本标签 `<x.y.z>-restic<restic版本>`（如 `1.0.1-restic0.19.1`），CNB 制品库与 Docker Hub 同打；未打 tag 的日常构建只出 `sha短号 + latest`。

## 五、CI 语义速查

| 层 | 行为 |
|---|---|
| 触发 | **仅手动**（分支详情页按钮；无 push/tag 自动构建） |
| 后端依赖 | `uv sync --frozen --extra dev`——严格按 `uv.lock`，lock 与 pyproject 不同步时**直接报错** |
| 前端依赖 | `pnpm install --frozen-lockfile`——严格按 `pnpm-lock.yaml` |
| 标签 | sha 短标签 + latest 固定；双版本标签仅当 HEAD 是 tag 目标 |
| Docker Hub | 未配置凭据（`dolphin738/my:docker.yml`）时自动跳过 |

## 六、常见坑

1. **改了 `pyproject.toml` 忘了重新 `uv lock`** → CI 的 `--frozen` 会直接失败（这是特性：强制你提交一致的两个文件）；
2. **CI 检出是浅克隆、无 tags** → 脚本里已做 `git fetch --tags origin`（失败不阻断），发版前记得把 tag push 上去；
3. **`uv run` 不带 `--no-sync` 会隐式尝试同步**——CI 脚本统一加 `--no-sync`，避免锁外解析；
4. 前端同理：升级用 `pnpm update`（或改 `package.json` 后 `pnpm install` 重写 `pnpm-lock.yaml`），提交锁文件 + 全量测试。
