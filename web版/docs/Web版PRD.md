## 1. 产品概述

### 1.1 一句话定位

把 restic 备份工具从命令行改造为**单容器 Web 应用**：自托管运维者通过浏览器完成仓库配置、备份源选择、定时策略、快照浏览与恢复，无需编写任何脚本或 YAML。

### 1.2 目标用户与画像

| 用户画像 | 特征 | 核心诉求 |
|---|---|---|
| 自托管个人玩家 | 家用服务器/NAS，跑 Docker，有 Duplicati/Veeam 等图形备份工具使用经验 | 界面操作、防误删、恢复不踩坑 |
| 小团队运维者 | 管理几台 VPS/物理机，维护 Web 服务与数据库 | 定时任务可靠、失败可见、能审计谁做了什么 |
| 安全敏感的自托管者 | 暴露公网或共享宿主机 | 默认安全（鉴权、最小权限、危险操作有确认门） |

共同点：熟悉 Docker 基础操作（能改 compose 并 `docker compose up`），但**不愿维护 bash 备份脚本**。

### 1.3 核心价值主张

1. **零脚本运维**：日常调整（仓库、凭据、策略、调度、通知、dump）100% 在 Web 界面完成，不碰 compose、不重启容器；
2. **全盘可备、增删零重启**：`/` 整盘挂载为 `/host`，备份源在界面任意勾选，加源不需要改挂载；
3. **恢复不踩坑**：P1 仅提供"恢复到时间戳子目录"这一默认路径，从产品层面杜绝误覆盖（P2 才开放覆盖确认流）；
4. **安全默认**：鉴权是 P1 第 0 项，无鉴权不上其他功能；危险操作三重确认 + append-only 审计。

## 2. 产品目标与成功指标

| # | 目标 | 成功指标（可衡量） |
|---|---|---|
| G1 | 快速上手：全新宿主机极简部署 | P1 DoD：全新宿主机 **30 分钟内**完成部署（含 bind-mount 属主处理）+ 配置仓库 + 首次备份 + 从快照恢复一份文件到时间戳子目录，全程有鉴权保护，首启改密流程完整走通 |

## 6. 非功能需求

| 类别 | 需求 |
|---|---|
| **安全** | ① 全部 API（含 SSE）走 cookie session 鉴权，SSE 禁用 query token；② 仓库密码永不入库、永不出 API；后端凭据 API 脱敏（仅 has_value + 来源）；③ restic 参数经固定白名单拼装，无自由命令透传；路径规范化 + 前缀校验；④ 危险操作三重确认 + append-only 审计（无更新/删除 API）；⑤ 登录防爆破（指数退避）+ 登录接口独立限流；⑥ `/data` 目录 chmod 700 且部署文档要求排除出宿主机其他备份工具范围；⑦ HTTPS 双轨（Q2 已裁决）：首选反代（部署文档含 Caddy 自动 HTTPS 示例），镜像内置"挂证书"式 TLS 选项（UI 配证书/私钥路径，无自动签发续期） |
| **性能** | ① snapshots/文件树 API 分页（limit/offset 或游标）或流式转发，前端虚拟滚动，支持数万条目不卡顿；② `--json` 逐行解析放线程池，不阻塞事件循环；③ SQLite：WAL + 单写连接 + busy_timeout=5000；④ 备份限速：策略字段 `--limit-upload/--limit-download`（KiB/s，0=不限）+ 进程级 nice/ionice 作 IO 优先级补充，P2 交付（Q5 已裁决） |
| **可用性** | ① 任务失败/skipped/锁残留/ro 档限制/pg 版本不匹配等，一律在 UI 给出明确原因与下一步动作，禁止静默失败；② 手动触发冲突返回 409 并提示"已有任务进行中"；③ 页面刷新不丢进度（日志尾部回放 + 续流）；④ 容器重启：running 标记 interrupted + 按策略补跑 + AUTO_UNLOCK 语义处理锁残留 |
| **兼容性** | ① 浏览器：支持 Chrome/Edge/Firefox 最近两个大版本 + Safari 最新版（需支持 EventSource 与 CSS 虚拟滚动方案）；**不支持 IE 及已停止安全更新的浏览器版本——支持/不支持清单写入部署文档（Q8 已裁决）**；② restic `--json` 字段随版本演进，解析层做版本适配（镜像固定版本，fixture 回归测试兜底）；③ 单实例部署，禁止水平扩容多副本（文档声明）；④ 界面语言：首版即中英双语，i18n（vue-i18n）架构 P1 预留（Q3 已裁决） |

## 7. 组件库选型（已裁决：Vue 3.5 + Naive UI）

**结论：已裁决 Naive UI（2026-10-10），与 Vite + Vue 3.5 配套使用**（Vue 3.6 目前处于 RC/Vapor Mode，不采用，待其稳定后可再评估升级）。

| 考量维度 | 评估 |
|---|---|
| 框架匹配 | Vue 3 原生组件库，专为 Vue 3 设计，无跨框架移植层；全量 TypeScript 编写，类型定义与 Vue 类型体系（SFC / `defineProps` / `defineEmits`）天然一致 |
| 表格/表单/向导类交互密集 | 强匹配：`n-data-table`（分页/筛选，内建 `virtual-scroll` 虚拟滚动）、`n-form`（联动/校验/脱敏字段禁用态）、`n-steps`（恢复向导/首启引导）、`n-modal` / `n-popconfirm`（三重确认弹窗）开箱即用 |
| 暗色模式 | 内置 `darkTheme`，经 `n-config-provider` 一行切换；自托管运维场景常驻服务器机房/夜间使用，暗色为实际需求 |
| 许可与体积 | MIT 许可，无商业组件陷阱；支持 tree-shaking 按需打包，组件样式内聚（CSS-in-JS），无全局样式污染，不打劫全局 CSS 命名空间 |
| 生态与本项目匹配 | 中文文档完善；SSE 进度用 `n-progress` + 自研 composable 订阅层即可，EventSource 为浏览器原生，无组件库依赖 |
| 备选对比 | Element Plus：生态体量大、Vue 3 组件最全，但设计语言偏移动端风格、按需引入配置较重（需 unplugin 系列插件）；Ant Design Vue：AntD 的 Vue 移植，能力齐全但暗色主题支持弱于 Naive UI。Naive UI 对"管理后台型表单密集 + 需要暗色"场景最匹配 |

配套约定：虚拟滚动列表（快照/文件树）优先用 `n-data-table` 的 `virtual-scroll` 属性，非表格场景（懒加载文件树）用 `@vueuse/core` 的 `useVirtualList` 兜底；SSE 统一封装为 Vue composable（`useJobStream`），组件不直接持有 EventSource。
