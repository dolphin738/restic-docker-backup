# AGENTS.md 与《代码审查规范》评审报告

> 评审日期：2026-10-11  
> 评审范围：`AGENTS.md`（55 行）、`docs/代码审查规范.md`（198 行）  
> 方法：主理人独立取证（25 条交叉引用核对 + 真实代码/命令实测）+ 架构师独立评审，两轮结论交叉验证后合并  
> 裁决：**规则设计质量高，工程质量描述失真**——架构类引用 19/19 全部可核实，CI/工具链/人员类引用大面积与仓库实况不符

## 一、总体结论

**这两份文档值得保留，规则本身是同类项目里质量明显偏上的水平**，但存在一个结构性问题：**它对"架构是什么"描述得极准，对"工程环境是什么"描述得极不准**。

25 条交叉引用中，19 条（架构决策 D2/D4/D5/D6/D7/D8、端点 E01–E32、方案 §6 注入防护、PRD US-A1/G3/Q3）**全部真实且主题精确对应**；而 6 条失实**无一例外集中在 CI 配置、lint 工具、人员角色、文件名**这类随代码演进而文档未跟的工程环境描述上。

**最该改的 3 件事**：

1. **修掉 6 处失实声明**（CI"已配置"eslint/vitest、owner 三处不同身份、`.github` 不存在却写 PR 门禁、`docs/Web版改造方案 v2.3.4` 这个打不开的路径）——失实比缺规则更伤信任，AI 会照着不存在的路径静默跳过；
2. **裁决 2 处"规范 vs 现有代码"冲突**（A1 被 auth 模块与 health 探针违反、A2 被 `exclusions.py` 硬编码前缀违反）——不裁决，严格执行规范的 reviewer 会去打回已合入的 P1 代码；
3. **把双文档同步从"约定"升级为"机制"**：红线正文单一事实源放规范，AGENTS.md 只留编号索引 + 可 grep 的自查命令，让"必须同时更新"不再依赖任何人的自觉。

## 六、双文档同步机制：改造建议

### 问题定性

现机制依赖"改一处必须记得同步另一处"，**R4 的 4 处漂移就是它已经失效的实证**。降级风险真实且严重：AGENTS.md `:3` 自称"写代码前必读"，说明它才是真正入口——**AI 不知道 S4/S5/S8 存在 → 写新路由不加 `require_session`、不校验 Origin → 且自己不会意识到违规**。

### 三层改造（按可靠性排序）

**第 1 层：编号索引替代正文复制**  
红线正文**只存在于规范 §3.1**，AGENTS.md 每条改为 `[S4] 鉴权与首启门 —— 详见规范 §3.1 S4` 形式。编号可 grep 校验存在性。

**第 2层：机器可校验的 grep 清单**（最关键）  
把每条红线变成一条能跑的断言，让"是否违规"从"靠人记得对照"变成"一条命令出结论"：

```bash
# scripts/verify_redlines.sh —— 任一断言失败即视为违反红线
grep -rn "shell=True\|os.system" backend/app/            && { echo "✗ S2 restic 参数注入"; exit 1; }
grep -rn "UPDATE audit_logs\|DELETE FROM audit" backend/app/ && { echo "✗ S6 审计 append-only 被破坏"; exit 1; }
grep -rn '"/host"\|"/sources"' backend/app/ --include=*.py \
  | grep -v constants.py | grep -v exclusions.py           && { echo "✗ A2 前缀硬编码"; exit 1; }
grep -rn "SELECT \|INSERT \|UPDATE " backend/app/ --include=*.py \
  | grep -v "app/db/" | grep -v "app/auth/"              && { echo "⚠ A1 复核：非仓储层的 SQL"; }
grep -rn "token=" backend/app/routers/                    && { echo "✗ S4 SSE 不得用 query token"; exit 1; }
```


注意第 4 条：脚本会**诚实地把 A1 的 4 处既有违反报出来**，从而"迫使裁决而不是掩盖"——这正是 R5 需要的效果。

**第 3 层：pre-commit 兜底**  
在 `.github/workflows` 落地前，先把上述脚本挂到 pre-commit。规范改动若未同步 AGENTS.md，断言清单会失败——**"必须同时更新"由钩子强制，不靠自觉**。
