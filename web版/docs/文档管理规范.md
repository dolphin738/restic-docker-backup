## 1. 文档分层与存放位置

所有知识文档放 `docs/`（唯一例外：`AGENTS.md` 在仓库根，它是索引不是知识文档）。分六层：

| 层 | 存放 | 权威性 | 现有文件 |
|---|---|---|---|
| 索引层 | 仓库根 `AGENTS.md` | 面向 AI 代理的红线**编号索引**，判定以规范 §3.1 为准 | AGENTS.md |
| 规范层 | `docs/` | 红线与审查标准**唯一权威** | 代码审查规范.md（§3.1 为红线唯一权威版本） |
| 方案层 | `docs/` | 需求/架构/技术决策的**唯一事实来源** | Web版PRD.md（需求池唯一权威）、架构设计文档.md（DB/API/流程/演进位）、Web版改造方案.md v2.3.4（技术决策与阶段计划） |
| 运维层 | `docs/` | 随交付维护的操作手册 | 部署指南.md、依赖升级指南.md、云端仓库安全基线.md |
| 过程层 | `docs/`（**必须带日期后缀**） | 时效产物，结论吸收后即归档 | 审查报告-未推送代码-2026-10-11.md、评审报告-AGENTS与代码审查规范-2026-10-11.md |
| 参考层 | `docs/` | 外部资料分析，供决策取证 | Duplicati三流程分析.md（保留：结论已归入改造方案，文首已标注；配套改造方案已归档 2026-10-15） |

**硬规则**：
1. 正式文档（规范/方案/运维）用**稳定命名、不带日期、不建副本**；版本号写在文档头（如 PRD v1.1、方案 v2.3.4），不进文件名；
2. 过程产物一律 `<类型>-<主题>-<YYYY-MM-DD>.md`，无日期的报告不许新建；
3. 同一主题只允许一个正式文档；新内容能吸收进现有章节的，**不新建文档**（见 §5 准入）。

## 2. 冲突裁决顺序

文档间出现矛盾时按此链裁决，**不得各取一半**：

1. 红线/审查标准 → `代码审查规范.md` §3.1（唯一权威）；
2. 需求边界/优先级 → `Web版PRD.md` 需求池；
3. 技术决策（选型/阶段/排期） → `Web版改造方案.md` v2.3.4；
4. 架构实现（DB/API/流程） → `架构设计文档.md`（红线涉及的 grep 线索以 AGENTS.md 索引为准，判定仍回规范 §3.1）；
5. 编号锚点双文档一致性由 `scripts/verify_redlines.sh` 机器校验，人工不裁决编号。

## 3. 生命周期与「结束的文档」处理

状态机：**草稿 → 活跃（被引用） → 定稿 → 归档/退役**。

| 结束情形 | 处理方式 |
|---|---|
| 结论已被上位文档吸收（如评审报告结论并入 AGENTS.md/规范） | 移入 `docs/archive/`，文件头加「已归档（YYYY-MM-DD）：结论见 X」，登记表标注 |
| 被新文档取代（如旧版方案被新版本替代） | 文件头加 `superseded by <新文档>` 标注后移入 `docs/archive/` |
| 一次性过程产物且无引用价值（临时排查记录等） | 经 owner 确认无任何引用后**删除**（git 历史兜底可追溯） |
| 参考资料类（如 Duplicati 分析） | 长期保留在 docs/，结论被方案吸收后在文首标注「结论已归入 X」 |

**纪律**：
- 归档/删除/移动文档**必须经 owner 确认**，AI 代理不自行执行（与 AGENTS.md「AI 不自行提交」同精神）；
- `docs/archive/` 内文档不参与构建、不被 CI/脚本引用，仅供追溯；
- 归档是移动不是删除：`git mv` 进 `archive/`，保留完整历史。

## 4. 命名规范

| 类型 | 规则 | 示例 |
|---|---|---|
| 正式文档 | 稳定名，无日期，版本号在文头 | 架构设计文档.md、Web版PRD.md |
| 过程产物 | `<类型>-<主题>-<YYYY-MM-DD>.md` | 审查报告-未推送代码-2026-10-11.md |
| 方案/参考 | 稳定名 + 文首标注状态（立项/已归档/结论已归入） | 对齐Duplicati的改造方案.md |

## 5. 新增文档准入

建新文档前过这三问，任一命中才建：

1. **能吸收吗**——内容能写进现有文档章节的，写进去，不新建（本规范 §1 硬规则 3）；
2. **需跨会话追溯吗**——过程结论（评审/审查/排查）需要留痕的，建过程文档（带日期），结论吸收后归档；
3. **是新知识类别吗**——确实无处安放的，建正式文档并登记进 §6 登记表。

**禁止**：建 README 式总览副本；同一主题双文档并行；把讨论原文直接存文档（须蒸馏为决策记录）；无日期报告。

## 7. 变更纪律

1. **裁决先行**：任何文档调整源于明确裁决（owner 指令或评审结论），不在文档里留「待定」却不记录裁决出处；
2. **权威优先改**：红线改动先改规范 §3.1，再同步 AGENTS.md 编号索引（AGENTS.md 维护约定）；需求改动先改 PRD，再同步架构 §11 追溯矩阵；
3. **连带同步**：新增/变更端点、错误码、配置键、阈值时，同批更新架构文档对应章节（§5.0/§4.3）与 compose；
4. **过程留痕**：方案类文档的重大修订在文首记「修订记录（日期 + 裁决内容）」，不覆盖历史决策。
