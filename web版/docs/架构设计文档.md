## 1. 架构总览

### 1.1 分层架构

```mermaid
graph TB
    subgraph FE["前端 SPA（Vite + Vue 3.5 + Naive UI）"]
        PAGES["页面层：登录 / 首启引导 / 仪表盘 / 仓库配置 / 备份源 / 策略调度 / 任务历史 / 快照浏览 / 恢复向导 / 通知 / 设置 / 审计"]
        QUERY["vue-query（TanStack Query for Vue，Server State）"]
        ZS["Pinia（UI State：会话/主题/全局提示）"]
        SSECLI["useJobStream composable（SSE 封装：Last-Event-ID 续传）"]
    end

    subgraph APP["FastAPI 应用层（单进程 asyncio）"]
        MW["中间件链：Origin/CSRF 校验 → Session 鉴权 → 审计埋点"]
        subgraph RT["路由层 routers/"]
            R1["auth / health / sources / config"]

            R3["snapshots / restore"]
            R4["backup_tasks（E34–E36，repo 作用域）"]

        end

            S4["OutputParser（线程池解析 --json）"]
            S5["PathMapper（/host 前缀 ↔ 原路径，唯一实现点）"]
            S6["SchedulerService（APScheduler per-task，R-013 本批落地）"]
            S7["DumpService（含 pg 版本探测，P2）"]

    end

    subgraph INFRA["基础设施层"]
        DB[("SQLite /data/restic.db<br/>WAL + 单写连接 + user_version 迁移<br/>六表 + repos/backup_tasks（0002）")]
        APS["APScheduler AsyncIOScheduler"]
        SP["subprocess → restic 0.19.1 静态二进制"]
        LOGF["任务日志文件 /data/jobs/&lt;id&gt;.log<br/>（SSE 回放 + 追加的持久底座）"]

    end

    PAGES --> QUERY & ZS & SSECLI
    QUERY & SSECLI -->|"fetch / EventSource"| MW
    MW --> RT
    RT --> SVC
    SVC --> REPO

    S3 --> SP
    S4 --- SP

    RT --> LOGF

    S9 --> REPO
```

要点：

- **三层后端**（路由-服务-仓储）+ 独立 auth 模块；DB 访问只存在于仓储层，路径映射只存在于 PathMapper——两处"唯一实现点"是防泄漏的关键约束；
- **SSE 的持久底座是任务日志文件而非内存队列**：日志先落盘、SSE 只是"按偏移回放 + 追加"，天然获得断点续传与容器重启后的进度可回放性；
- **--json 解析放线程池**：解析为 CPU 密集，避免阻塞事件循环（方案 §5）。

### 1.2 部署拓扑

```mermaid
graph LR
    U["浏览器"] -->|"HTTPS"| RP["反向代理（用户自备）<br/>nginx: X-Accel-Buffering: no<br/>SSE 禁缓冲"]
    RP -->|"HTTP :8000"| C["容器 restic-web:&lt;app&gt;-restic&lt;v&gt;<br/>user: 0:0（默认）/ 1000:1000"]

    subgraph HOST["宿主机"]
        C
        M1["/:/host（ro|rw，HOST_MOUNT_MODE）"]
        M2["/restore:/restore（恢复目标）"]
        M3["/mnt/.../repo:/repo（仅本地仓库）"]
        M4["./data:/data（chmod 700，非 root 档须 chown 1000:1000）"]
        M5["./cache:/cache/restic"]
        M6["./secrets/restic-pass:/run/secrets/restic-pass:ro"]
    end

    C -->|"s3:// b2://"| OBJ[("S3 / B2 对象存储")]
    C -->|"PGHOST/PGPORT TCP"| PGDB[("PostgreSQL / MySQL / MariaDB")]
```

- 单实例强约束（禁止多副本，方案 §4）；`HEALTHCHECK` 探测 `GET /api/health`；
- 非 root 档部署前置：`chown -R 1000:1000 ./data ./cache ./secrets`，否则 SQLite 建库失败容器起不来；
- **HTTPS 双轨（Q2 裁决）**：上图为首选反代路径（终结 TLS + SSE 禁缓冲）；镜像内置"挂证书"式 TLS——config `server.tls_cert`/`server.tls_key` 齐备时 uvicorn 以 `ssl_certfile`/`ssl_keyfile` 直接启动（无自动签发续期），未配置则纯 HTTP 供反代终结（§4.3 键表）。
- **前端 SPA 由后端同源提供**（单容器方案 §2，不引入 nginx 第二进程）：构建阶段产出 `dist` 并 COPY 进运行时的 `/app/webroot`（`settings.static_dir`，环境变量 `STATIC_DIR` 可覆盖）；`create_app()` 在**业务路由之后** `mount("/", StaticFiles(html=True))`，保证 `/api` 优先匹配；404 处理器仅对 `GET/HEAD`、非 `/api` 前缀、末段无扩展名的请求回落 `index.html`（SPA 深链刷新），其余一律返回统一 JSON 错误。目录不存在时不挂载——`/` 仍是 JSON 404，本地开发页面由 Vite dev server 提供。

### 1.3 关键架构决策汇总

| #  | 决策                                                            | 理由（出处）                                                 |
| -- | ------------------------------------------------------------- | ------------------------------------------------------ |
| D1 | 单容器 + restic 静态二进制内嵌，版本随镜像 tag 固定                             | 版本确定性 + 仓库格式安全（方案 §4）                                  |
| D2 | SQLite 单库 + WAL + aiosqlite 单写连接                              | 自托管规模单实例足够；单写连接规避 SQLITE_BUSY（方案 §5）                   |
| D3 | 调度统一 cron 触发器（策略级 + 全局缺省），P1 即按多策略建表                          | 消除 interval/cron 双轨；P2 开放多策略零改表（方案 §4.1/§5）            |
| D4 | P1 恢复仅"时间戳子目录"，不存在任何覆盖路径                                      | 误操作零事故（PRD G3）；覆盖比对层 P2 自研                             |
| D5 | 鉴权是 P1 第 0 项，cookie session 全端点（含 SSE）统一                      | 无鉴权 + rw 全盘挂载 = 裸奔（方案 §6.1/§8）                         |
| D6 | SSE 持久底座 = 任务日志文件 + last_event_id 游标                          | 断点续传、刷新回放、重启可回放                                        |
| D7 | 路径映射/DB 访问各只有一个实现点（PathMapper / repositories/）                | 防止 `/host` 前缀语义泄漏到业务代码                                 |
| D8 | 内置排除集为代码常量（语义核心集 + 按 `RESTIC_WEB_MODE` 派生前缀，不存 DB），UI 可追加不可删减 | 单一事实来源，host/sources 两模式不漂移（方案 §3.1 v2.3.2）；"不可删减"由代码保证 |

### 4.8 backup_tasks（备份任务 · 0002 新增，选项②核心）

```sql
CREATE TABLE IF NOT EXISTS backup_tasks (
    id                  INTEGER PRIMARY KEY,
    repo_id             TEXT NOT NULL DEFAULT 'default' REFERENCES repos(id),  -- E7：第一天带外键
    name                TEXT NOT NULL,
    enabled             INTEGER NOT NULL DEFAULT 1,
    tag                 TEXT NOT NULL UNIQUE,     -- 自动生成只读：task-<id>（greenfield 无 legacy 继承）
    sources             TEXT NOT NULL,            -- JSON 数组，容器前缀形态（同 policies 口径）
    excludes            TEXT NOT NULL,            -- JSON 数组；内置排除集不入库（D8）
    keep_last           INTEGER NOT NULL DEFAULT 0,
    keep_hourly         INTEGER NOT NULL DEFAULT 0,
    keep_daily          INTEGER NOT NULL DEFAULT 0,
    keep_weekly         INTEGER NOT NULL DEFAULT 0,
    keep_monthly        INTEGER NOT NULL DEFAULT 0,
    keep_yearly         INTEGER NOT NULL DEFAULT 0,
    group_by            TEXT NOT NULL DEFAULT 'host,paths,tags',
    cron                TEXT,                     -- 空 → 回退全局缺省 schedule.cron_default（§7.4）
    one_file_system     INTEGER NOT NULL DEFAULT 0,
    compression         TEXT NOT NULL DEFAULT 'auto',
    check_sample_ratio  REAL NOT NULL DEFAULT 0.02,
    monthly_full_day    INTEGER NOT NULL DEFAULT 1,
    prune_interval_days INTEGER NOT NULL DEFAULT 7,
    limit_up_kibps      INTEGER NOT NULL DEFAULT 0,   -- KiB/s，0=不限
    limit_down_kibps    INTEGER NOT NULL DEFAULT 0,
    dry_run_pending     INTEGER NOT NULL DEFAULT 0,   -- R-026-08 首跑门：创建置 1，E36 预览成功清 0
    last_run_at         TEXT,                          -- 调度记账（先记账后执行，§6.8）
    created_at          TEXT NOT NULL,
    updated_at          TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_backup_tasks_repo ON backup_tasks(repo_id);
```

**与 `policies` 的关系（决策 1:1）**：

- 任务即策略实体：`backup_tasks` 与 `policies` **字段同构**，任务表新增 `repo_id` / `dry_run_pending`，不设 `is_default`（策略的「恒一条默认」约束在任务域不存在）；
- `policies` 表**保留为 legacy**：仅供历史 `jobs.policy_id` 溯源与其只读端点（E08–E11 写路径恒 409），不再出现在任何 UI 写路径；
- **无 `status` 列**：任务状态是派生值（§5.1 E34 卡片），避免双状态源漂移；`enabled` 是调度门而非状态机迁移。

**tag 规则（共享知识）**：新建任务由 `TaskRepo.create` 插入后同方法内回写 `tag='task-<id>'`（单写连接串行无竞态，`UNIQUE(tag)` 兜底）；更新路径显式剔除 tag（`TaskRepo.update`），客户端提交一律忽略——防止改 tag 导致 forget `--tag` 误删他任务快照。greenfield 裁决下**无 legacy tag 继承分支**。

**删除任务的解绑语义（Q7）**：`DELETE` 一条任务 → `jobs.task_id` 经外键 `ON DELETE SET NULL` 置空（历史行与日志保留、脱离归属）；仓库内该 tag 的快照**不动**（forget 是唯一删快照路径）。库中**不存在**指向已删任务的孤儿 `task_id` —— 外键本身禁止该形态。

字段对应关系：E03/E06 ↔ config、E08–E11 ↔ policies（legacy）、E12–E14/E16 ↔ jobs、E26 ↔ audit_logs、**E34–E36 ↔ backup_tasks**、§6.1 时序 ↔ admin_account/sessions。


## 5. API 详细设计

### 5.0 统一约定

**统一错误响应**（所有非 2xx）：

```json
{ "code": "JOB_CONFLICT", "message": "已有任务进行中", "data": { "running_job_id": "01JAAA…" } }
```

| code               | HTTP | 场景                                             |
| ------------------ | ---- | ---------------------------------------------- |
| `VALIDATION_ERROR` | 422  | 参数/路径校验失败                                      |
| `UNAUTHORIZED`     | 401  | 未登录 / 会话过期                                     |
| `FORBIDDEN`        | 403  | CSRF Origin 校验失败 / 首启未改密（`BOOTSTRAP_REQUIRED`） |
| `NOT_FOUND`        | 404  | 资源不存在                                          |
| `JOB_CONFLICT`     | 409  | 同仓库已有 running/pending 任务（方案 §5：手动触发拒绝不排队）      |
| `ACCOUNT_LOCKED`   | 429  | 登录锁定（data 带 `retry_after`）                     |
| `RATE_LIMITED`     | 429  | 登录接口限流                                         |
| `INTERNAL`         | 500  | 兜底（不回内部细节）                                     |
| `TASK_RUNNING`     | 409  | 任务正在运行/等待中，拒绝删除（E35c；data 带 `running_job_id` + `task_name`；选项②新增） |
| `REPO_NOT_FOUND`   | 404  | repo 作用域 id 不存在（E34–E36 路径前缀；P2 仅 `default`；data 带 `repo_id`；选项②新增） |

> 端点级扩展码（响应格式同上表）：`400 PATH_OUT_OF_PREFIX`（E05）、`409 ENV_OVERRIDDEN`（E07）、`409 DEFAULT_POLICY_IMMUTABLE`（E11）、`409 NOT_CANCELLABLE`（E16）、`403 RESTORE_FORBIDDEN`（E19）、`410 BOOTSTRAP_SHOWN`（Bootstrap）、`409 TASK_RUNNING`（E35c）、`404 REPO_NOT_FOUND`（E34–E36）——见各端点定义。
>
> 其余已登记码（2026-10-11 补全，与 `app/constants.py` 的 `ERROR_STATUS` 对齐，此前本表遗漏 6 项）：`500 RESTIC_FAILED`（restic 子进程非 0 退出，message 不回显内部细节）、`409 POLICY_WRITE_CLOSED`（非默认策略写/删，E10）、`409 READONLY_KEY`（写只读派生源，`repo.type`）、`401 PASSWORD_WRONG`（E28 改密）、`403 CSRF_ORIGIN`（Origin/Referer 校验失败）、`403 BOOTSTRAP_REQUIRED`（首启未改密，业务 API 压制）。
> **维护约定**：`ERROR_STATUS` 新增条目时须同 PR 更新本表（规范 §3.2「错误码登记」为该要求的审查依据）。

**分页约定**：列表类 `?limit=50&offset=0` → `{"items": [...], "total": 123, "limit": 50, "offset": 0}`；文件树用游标 `?cursor=<opaque>&limit=200` → `{"items": [...], "next_cursor": "…" | null}`。

**鉴权**：除 E04 与 E01、bootstrap 外全部要求有效 session；写方法（POST/PUT/DELETE）额外要求 Origin 同源（§8）。

### 5.1 端点明细（方案 §5 全覆盖；E01–E32）

**E01 `POST /api/auth/login`**（P1，免鉴权）

```json
// 请求 {"password": "..."}
// 200：Set-Cookie: rw_session=<token>; HttpOnly; SameSite=Strict; Path=/; Max-Age=86400
// 401 PASSWORD_WRONG / 429 ACCOUNT_LOCKED / 429 RATE_LIMITED / 403 CSRF_ORIGIN
```

**E02 `POST /api/auth/logout`**（P1）：销毁服务端 session + 清 cookie；200 `{"code":"ok"}`。

**E03 `GET /api/auth/me`**（P1）：

```json
{ "authenticated": true, "must_change_password": false,
  "mode": "host", "host_mount": "rw", "user": "root" }   // 供四象限卡（US-G2）
// 401 UNAUTHORIZED / 403 BOOTSTRAP_REQUIRED（data 带 bootstrap 步骤提示）
```

**E04 `GET /api/health`**（P1，免鉴权）：HEALTHCHECK 用；200 `{"status":"ok","db":"ok"}`（不校验仓库连通，避免拖垮探测）。

**E05 `GET /api/sources?path=/etc/nginx`**（P1）：目录浏览（按 RESTIC_WEB_MODE 定位 `/host`|`/sources` 模式根下）。

> 入参 `path` 语义修订（P1 实现定案）：**收展示路径**（如 `/etc/nginx`；缺省为模式根），服务端内部经 PathMapper `to_snapshot` 还原为容器路径；**兼容旧文档示例的容器路径形态**——`/host`、`/sources` 前缀照常接受（按当前模式白名单校验）。响应 `items[].display_path` 一律为剥前缀的展示路径。

```json
{ "path": "/etc", "items": [ {"name":"nginx","type":"dir","display_path":"/etc/nginx"} ],
  "next_cursor": null }
```

```python

class SchedulerService:
    def __init__(self, tasks: TaskRepo, runner: JobRunner, config: ConfigRepo,
                 settings: Settings | None = None, *, jobs: JobRepo) -> None:
        """``jobs`` 为设计稿未列的显式注入：catchup/prune 判定必须读 jobs 表，
        且 A1 要求 DB 访问只经仓储——JobRunner 未暴露该查询，故显式注入。"""

    async def start(self) -> None:
        """AsyncIOScheduler.start() → reload() → catchup_on_startup()（lifespan 接线，§6.8）。"""
    async def shutdown(self) -> None:
        """scheduler.shutdown(wait=True)；时序上先于 JobRunner.on_shutdown（先停调度再收尾子进程）。"""

    async def reload(self) -> None:
        """全量重建 backup 触发器：enabled=1 且有效 cron 非空的任务各一个
        CronTrigger.from_crontab（job id ``backup-task-<id>``，replace_existing），
        随后移除已不存在/已暂停/无有效 cron 的遗留 job。任务增改删后调用（保存即生效不重启）。"""

    async def catchup_on_startup(self) -> None:
        """补跑：当天首个应触发点已过（``get_next_fire_time(None, 当天 00:00(tz))`` ≤ now）
        且该任务无 finished_at ≥ 该点的成功 backup job → submit(scheduled) 一次。"""

    def next_fire_time(self, task: Task) -> str | None:
        """E34 卡片「下次运行」；enabled=0 或无有效 cron（含无法解析）→ None（已暂停/仅手动）。"""
    async def _due_for_prune(self, task: Task) -> bool:
        """prune 到期判定（N3 裁决 2026-10-14 语义修正）：
        距上次**成功 forget** 超 prune_interval_days（原「距上次成功 backup」在备份
        正常进行时永不触发，等于配置形同虚设）；从未 forget 且有成功备份 → 首次到期。
        E34 卡片 ``prune_due`` 与自动 forget 共用本判定。"""
    async def maybe_auto_forget(self, task_id: int) -> None:
        """N3 开放的自动裁剪：backup 成功回调触发；护栏 = enabled + interval>0 +
        到期 + 任务至少一个 keep_*>0（0=未启用）；提交 scheduled forget + --prune，
        仓库忙走既有冲突语义（cancelled 跳过，下轮再判）。"""
    async def _fire_backup(self, task_id: int) -> None:
        """触发链：读任务 → enabled 复核 → sleep(jitter) → set_last_run_at(记账) → submit。"""

    def _effective_cron(self, task: Task) -> str | None:
        """有效 cron 解析（单一实现点）：task.cron → config ``schedule.cron_default`` → 无（仅手动）。"""
    def _build_trigger(self, task_id: int, cron: str) -> CronTrigger | None:
        """``CronTrigger.from_crontab(cron, timezone=tz)``；**仅收 5 字段**，6 字段解析失败
        → WARNING + None（该任务退化为仅手动）。见 §14 X5 与 §12 V3。"""
```

**关键语义**：① 时区 = `config.timezone` → `settings.tz` → UTC（cron 解释与「当天」判定同源）；② jitter = `config.schedule.jitter`（缺省 300s，上限 3600s），在 fire 回调内 sleep，顺序为「查 enabled → jitter → 记账 → submit」（先记账后执行防崩溃重复触发）；③ 冲突不排队——scheduled 提交遇活跃 job 落 cancelled + `job.skipped_conflict`，下个周期自然再试（E1）。

## 8. 鉴权实现（R-001）

| 项       | 实现                                                                                                                                                                                 |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cookie  | 名 `rw_session`；`HttpOnly` + `SameSite=Strict` + `Path=/`；反代 HTTPS 时加 `Secure`（由 settings `force_https` 或检测 `X-Forwarded-Proto`）；服务端只存 SHA-256(token)（§4.2）                         |
| 会话有效期   | 24h 滑动：每次认证请求刷新 `last_seen_at`，`expires_at=last_seen_at+24h`；登出 DELETE 行（E02）；过期行由启动期惰性清理                                                                                          |
| CSRF    | **写方法**（POST/PUT/DELETE）校验 `Origin`（缺失则回退 `Referer`）host 与 `Host`/`X-Forwarded-Host` 同源，不一致 403 `CSRF_ORIGIN`；SameSite=Strict 为第一道，Origin 校验为第二道（双保险，兼容非浏览器客户端禁用场景为零——本产品只有浏览器客户端） |
| 密码哈希    | argon2-cffi 默认 PasswordHasher（默认 type 即 id 变体）：`time_cost=3, memory_cost=65536(64MiB), parallelism=4`；argon2 不可用时降级 bcrypt（cost=12）——编译期选择，运行期常量                                                       |
| 登录锁定    | 计数持久化于 `admin_account`（failed_attempts/lock_level/locked_until，§4.1）——**存 DB 不存内存，容器重启不清零**（防绕过）；5 次失败 → 锁 5min×2^level，上限 1h；成功登录清零                                               |
| 登录限流    | 进程内固定窗口：同 IP 登录接口 5 次/分钟（内存实现，重启清零可接受——锁定持久化已兜底）；429 `RATE_LIMITED`                                                                                                                |
| 中间件顺序   | `main.py` 中间件链：① Origin/CSRF（仅写方法）→ ② Session 鉴权（FastAPI dependency `require_session`）→ ③ Bootstrap 门（must_change=1 时仅放行 auth/bootstrap 相关）→ ④ 审计埋点（危险操作路由显式调用 AuditService，非全局）   |
| SSE 鉴权  | `EventSource` 无法自定义 header → **不用 query token**；`/api/jobs/{id}/stream` 与普通 API 走同一 `require_session` dependency（cookie 自动携带）；中间件链对 stream 端点完全一致（§8 中间件位置即在此）                     |
| 仓库密码/凭据 | 密码文件永不入库不出 API（只回挂载状态）；凭据 API 脱敏 has_value + source；Job Runner spawn 时注入 env                                                                                                       |

### 9.2 状态管理与数据层

- **Server State（@tanstack/vue-query）**：全部 REST 请求；失效策略——任务终态事件后 invalidate `jobs`/`snapshots`；策略保存后 invalidate `policies`（TanStack Query 官方 Vue 适配版，失效策略不变）；
