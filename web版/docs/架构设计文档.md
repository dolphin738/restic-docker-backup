> **v1.10 修订（2026-10-27，rclone 配置管理工具：Q17 有边界放宽）**：
> - **新增 E48–E51**（§5.1）：`GET /api/rclone/configs` / `POST` / `PUT` / `DELETE /api/rclone/config/{remote_name}`——conf 段的查询、生成、编辑、删除。**Q17 档位有边界放宽**：仅**非 OAuth 类型**（crypt/webdav，凭据由用户自填）可生成与字段级编辑；OAuth 网盘段不可编辑（真实恢复须跑 `rclone authorize` 授权流），但**可删除**（清理废弃远端，确认门加重提示 + 审计留痕）；宿主机手工配置的 s3/sftp 同理（删除放开、编辑待进注册表）。
> - **写入路径 = 官方 rclone CLI**（`config create/update/delete`，`--obscure` 内置）而非自研 INI 手术：官方自带临时文件 + 双 rename 原子替换 + 备份。**由此 conf 挂载形态从单文件改为目录**（`./rclone:/etc/rclone:rw`）——真机实证单文件 bind mount 下 CLI 写入**退出码 0 但零落盘**且写操作挂住（详见《rclone配置生成工具设计方案.md》§12）；该修正同时使 OAuth token 回写真正可用（原「必须 `:rw`」的前提）。
> - 新增错误码 `RCLONE_UNAVAILABLE`（503）；审计动作 ×3 `rclone.config_append`/`_edit`/`_delete`（S6 清单 17→20，见《代码审查规范》v1.14）。§3 目录树与 §11 追溯矩阵 R-022 行同步。
> **v1.9 修订（2026-10-23，远端仓库明文暴露面收口：init 后密钥身份中性化 + 只读密钥可见性）**：
> - **init 后密钥身份自动中性化**（新服务 `services/repo_keys.py` 的 `neutralize_repo_key()`）：restic `keys/<id>` 是仓库里**唯一明文**文件，其 `username`/`hostname` 落在对象存储上对云商可见 → init 成功后自动 `key add --user svc-backup --host repo --new-password-file <**init 用的同一份**口令文件>` 再造一个中性 key，随后 `--key-hint <新 id> key remove <旧 id>` 删掉带真实身份的那个（**口令不变**，用户无感）。**幂等**（已中性化/多 key 即跳过）、**不抛**（任一步失败只记日志并返回 `False`，绝不把已成功的 init 反转成 failed）。覆盖两个 init 落点——`rebuild` 路由与作业类型 `init`（JobRunner success 终态）；未来新增 init 路径须复用同一函数（接入三要素、覆盖边界与最大坑见《云端仓库安全基线.md》§4.4）。
> - **新端点 E47 `GET /api/repos/{repo_id}/keys`**（§5.1，只读）：`restic key list --json` → `{overall, keys[], probe_error}`，`overall` 四态 `neutralized`/`exposing`/`mixed`/`unknown`。**只回展示白名单字段**（`id`/`id_full`/`user`/`host`/`created`/`created_tz`/`current`/`neutral`）；`data`（master key 密文）与 KDF 参数（`salt/N/r/p`）**绝不进 API**（少给一份仓库指纹）。**不复用 E42 的 30s TTL 缓存**——「是否已中性化」是安全判定，缓存会误导；无审计（只读探测，援 E45 先例）。
> - **白名单扩**（`services/restic.py`）：`WhitelistArgs` 增 `key_user`/`key_host`/`key_hint`；`--key-hint` 落 `_global_flags`（verb **之前**，`_assert_key_id` 校验「8~64 位小写十六进制」），`key add` 的 `--user`/`--host` 过 `_assert_safe_value`。**`--key-hint` 是必需项而非可选优化**：新旧 key 同口令时 restic 先解出哪个不确定，不加会撞 `refusing to remove key currently used`（restic 0.18.0 真机实证）。
> - 前端：仓库状态卡新增「密钥身份」小节（`pages/repo/KeyIdentity.vue`，自带 `useQuery(['repo','keys',id])`，不并入页面 30s 状态查询），与左侧连接态**左右并排**、按内容收缩 + 垂直居中、**无分隔线**，三条告警（last_error / 口令文件缺失 / 锁残留）通栏下沉到分栏下方；≤640px 回落上下堆叠。`created` 由 restic 按子进程 TZ 渲染且**不带时区标记** → 服务端补 `created_tz` 标注并**不换算**（C8 单一时间语义）。
> - §7.1 `ResticCmd.build` 的 verb 清单补齐 `copy`/`key`/`repair`/`recover`（v1.6-D / 批次 B 已落地但签名块漏列），并删去重复的旧块。

> **v1.7 修订（2026-10-20，前端仓库页「目标位置」模块复刻 + Windows 子进程防护；API 契约不变）**：
> - **S3 URL 方言修正（事实核验，推翻此前拼法）**：restic 0.19.1 原生语法为 `s3:<endpoint>/<bucket>[/<prefix>]`——**endpoint 与 bucket 之间是斜杠**（冒号仅用于协议头或 `host:port`）；此前按 `s3://bucket/...` 组译，落库即错地址。前端字段组改为「endpoint（必填）+ bucket + prefix」，path 为空时不补尾斜杠（与解析严格互逆）。同期**退役** URL 区域段与死凭据键 **`AWS_ENDPOINT_URL`**（实证：restic 0.19.1 不读该环境变量，其 minio-go v7.1.0 依赖零引用）；区域语义由 `cred.aws_default_region` 承担。全八类型逐一比对结论：**仅 s3 一种错误**，b2/gs/azure/sftp/rest/rclone/local 均符合 restic 原生。
> - **子进程事件循环硬约束（Windows，新增 §7.10）**：uvicorn 裸 `--reload` 在 Windows 强制 `SelectorEventLoop`，其 `create_subprocess_exec` 抛 `NotImplementedError`（`asyncio/base_events.py:539`）→ restic/rclone **全部子进程操作 500**（真机实证：rclone 探测报「服务器内部错误」）。四层防护落地：`constants.SUBPROCESS_LOOP_HINT`、`rclone.list_remotes` 降级 `available=false` + `reason`、`restic.spawn` 转 `ResticFailedError`、`main.py` lifespan 启动自检 error。**启动纪律：本机必须 `--loop none`**（`dev-scripts/dev.ps1 restart backend` 已内置）；Linux/Docker 无此问题。护栏 `tests/test_subprocess_loop_guard.py`。
> - 前端同步：仓库页两态交互（列表态 ↔ 编辑态整页替换）、类型驱动字段组、测试按钮状态机（新建态「创建并测试」，后端 `testRepo` 读已落库配置故顺序恒为先存后测）、审计日志动作名/详情中文化（i18n 嵌套键 + `te()` 回落）。后端除上述防护外**零业务改动**。

```mermaid
graph LR
```

- 单实例强约束（禁止多副本，方案 §4）；`HEALTHCHECK` 探测 `GET /api/health`；
- 非 root 档部署前置：`chown -R 1000:1000 ./data ./cache`，否则 SQLite 建库失败、密码文件不可读，容器起不来；
- **HTTPS 双轨（Q2 裁决）**：上图为首选反代路径（终结 TLS + SSE 禁缓冲）；镜像内置"挂证书"式 TLS——config `server.tls_cert`/`server.tls_key` 齐备时 uvicorn 以 `ssl_certfile`/`ssl_keyfile` 直接启动（无自动签发续期），未配置则纯 HTTP 供反代终结（§4.3 键表）。
- **前端 SPA 由后端同源提供**（单容器方案 §2，不引入 nginx 第二进程）：构建阶段产出 `dist` 并 COPY 进运行时的 `/app/webroot`（`settings.static_dir`，环境变量 `STATIC_DIR` 可覆盖）；`create_app()` 在**业务路由之后** `mount("/", StaticFiles(html=True))`，保证 `/api` 优先匹配；404 处理器仅对 `GET/HEAD`、非 `/api` 前缀、末段无扩展名的请求回落 `index.html`（SPA 深链刷新），其余一律返回统一 JSON 错误。目录不存在时不挂载——`/` 仍是 JSON 404，本地开发页面由 Vite dev server 提供。

### 1.3 关键架构决策汇总

| #  | 决策                                                            | 理由（出处）                                                 |
| -- | ------------------------------------------------------------- | ------------------------------------------------------ |
| D1 | 单容器 + restic 静态二进制内嵌，版本随镜像 tag 固定                             | 版本确定性 + 仓库格式安全（方案 §4）                                  |
| D2 | SQLite 单库 + WAL + aiosqlite 单写连接                              | 自托管规模单实例足够；单写连接规避 SQLITE_BUSY（方案 §5）                   |
| D3 | 调度统一 cron 触发器（策略级 + 全局缺省），P1 即按多策略建表                          | 消除 interval/cron 双轨；P2 开放多策略零改表（方案 §4.1/§5）            |
| D4 | P1 恢复仅"时间戳子目录"，不存在任何覆盖路径                                      | 误操作零事故（PRD G3）；覆盖比对层 P2 自研                             |
| D5 | 鉴权是 P1 第 0 项，cookie session 全端点（含 SSE）统一                      | 无鉴权 + rw 全盘挂载 = 裸奔（方案 §6.1/§8）                         |
| D6 | SSE 持久底座 = 任务日志文件 + last_event_id 游标                          | 断点续传、刷新回放、重启可回放                                        |
| D7 | 路径映射/DB 访问各只有一个实现点（PathMapper / repositories/）                | 防止 `/sources` 前缀语义泄漏到业务代码（A0 后唯一备份源前缀）             |

## 4. 数据库 Schema（DDL）

八张表：六张 P1 一次性建齐于 `backend/app/db/migrations/0001_init.sql`（§4.1–§4.6），另两张随选项②于 `0002_multi_backup_tasks.sql` 建（§4.7 `repos`、§4.8 `backup_tasks`，同脚本并为 `jobs` 加 `task_id` 列，见 §4.5 注）。时间列统一 `TEXT`（ISO 8601 UTC）；布尔以 `INTEGER 0/1` 表示。

### 4.1 admin_account（单行表：鉴权 + 首启引导状态）

```sql
CREATE TABLE admin_account (
    id                       INTEGER PRIMARY KEY CHECK (id = 1),  -- 恒单行
    password_hash            TEXT NOT NULL,    -- argon2-cffi 默认 PasswordHasher（id 变体）；bcrypt 降级时以 "$2b$" 前缀区分（§8）
    must_change              INTEGER NOT NULL DEFAULT 1,          -- 1=首启未改密；Bootstrap 门（§5.1）依据
    bootstrap_shown          INTEGER NOT NULL DEFAULT 0,          -- 随机密码是否已展示（仅一次；1 后再取 → 410 BOOTSTRAP_SHOWN）
    bootstrap_password_hash  TEXT,                                 -- 首启随机密码哈希；改密完成后置 NULL
    failed_attempts          INTEGER NOT NULL DEFAULT 0,          -- 登录失败计数（存 DB 防容器重启清零，§8）
    lock_level               INTEGER NOT NULL DEFAULT 0,          -- 指数退避级数：锁定时长 = 5min × 2^lock_level，上限 1h
    locked_until             TEXT,
    updated_at               TEXT NOT NULL
);
```

### 4.2 sessions（服务端会话，24h 滑动续期）

```sql
CREATE TABLE sessions (
    token_hash    TEXT PRIMARY KEY,   -- SHA-256(会话 token)；明文 token 只存在于 cookie，不落库不落日志
    last_seen_at  TEXT NOT NULL,      -- 每次认证请求刷新（滑动续期）
    expires_at    TEXT NOT NULL,      -- = last_seen_at + 24h；过期行由启动期惰性清理（§8）
    created_at    TEXT NOT NULL
);
```

### 4.3 config（KV 配置 + 全局键表）

```sql
CREATE TABLE config (
    key         TEXT PRIMARY KEY,
    value       TEXT,                            -- 敏感项（cred.*）明文落盘程度与 compose env 等价（§6.1）
    source      TEXT NOT NULL DEFAULT 'ui',      -- 'ui' | 'env'：compose 环境变量覆盖；E07 对 source='env' 的键返回 409 ENV_OVERRIDDEN
    updated_at  TEXT NOT NULL
```

## 5. API 详细设计

### 5.0 统一约定

**统一错误响应**（所有非 2xx）：

```json
{ "code": "JOB_CONFLICT", "message": "已有任务进行中", "data": { "running_job_id": "01JAAA…" } }
```

| code               | HTTP | 场景                                             |
| ------------------ | ---- | ---------------------------------------------- |
| `VALIDATION_ERROR` | 422  | 参数/路径校验失败                                      |
| `UNAUTHORIZED`     | 401  | 未登录 / 会话过期                                     |
| `FORBIDDEN`        | 403  | CSRF Origin 校验失败 / 首启未改密（`BOOTSTRAP_REQUIRED`） |
| `NOT_FOUND`        | 404  | 资源不存在                                          |
| `JOB_CONFLICT`     | 409  | 同仓库已有 running/pending 任务（方案 §5：手动触发拒绝不排队）      |
| `ACCOUNT_LOCKED`   | 429  | 登录锁定（data 带 `retry_after`）                     |
| `RATE_LIMITED`     | 429  | 登录接口限流                                         |
| `INTERNAL`         | 500  | 兜底（不回内部细节）                                     |
| `TASK_RUNNING`     | 409  | 任务正在运行/等待中，拒绝删除（E35c；data 带 `running_job_id` + `task_name`；选项②新增） |
| `REPO_NOT_FOUND`   | 404  | repo 作用域 id 不存在（E34–E36 路径前缀；P2 仅 `default`；data 带 `repo_id`；选项②新增） |
| `REPO_NOT_EMPTY`   | 409  | 仓库下仍有 backup_tasks 或 running/pending 作业，拒绝删除（E41；data 带 `repo_id` + `tasks`/`active_jobs` 计数；终态历史随仓库级联删除；R-023 新增） |
| `CREDENTIAL_DECRYPT_FAILED` | 500 | 凭据密文无法解密（R-025：密码文件被更换/数据被篡改；message 不回显明文或密文） |

> 端点级扩展码（响应格式同上表）：`400 PATH_OUT_OF_PREFIX`（E05/E19 原位分支）、`409 ENV_OVERRIDDEN`（E07）、`409 NOT_CANCELLABLE`（E16）、`403 RESTORE_FORBIDDEN`（E19/E20）、`410 BOOTSTRAP_SHOWN`（Bootstrap）、`409 TASK_RUNNING`（E35c）、`404 REPO_NOT_FOUND`（E34–E36）——见各端点定义。**P2 收尾批次（R-015/017/019）零新增错误码**：所有新失败形态均归入既有码（422 VALIDATION_ERROR 门禁 / 403 RESTORE_FORBIDDEN 双重锁 / 400 PATH_OUT_OF_PREFIX 越界），未扩 `ERROR_STATUS` 面。
>
> 其余已登记码（2026-10-11 补全，与 `app/constants.py` 的 `ERROR_STATUS` 对齐；2026-10-15 Q1 选删同步：`409 POLICY_WRITE_CLOSED`（E10）/`409 DEFAULT_POLICY_IMMUTABLE`（E11）已随 policies 遗留面删除，`ERROR_STATUS` 不再含 POLICY 码——历史记载见 §4.4/§5.1 E08–E11 删除条目）：`500 RESTIC_FAILED`（restic 子进程非 0 退出，message 不回显内部细节）、`409 READONLY_KEY`（写只读派生源，`repo.type`）、`401 PASSWORD_WRONG`（E28 改密）、`403 CSRF_ORIGIN`（Origin/Referer 校验失败）、`403 BOOTSTRAP_REQUIRED`（首启未改密，业务 API 压制）。
> **维护约定**：`ERROR_STATUS` 新增条目时须同 PR 更新本表（规范 §3.2「错误码登记」为该要求的审查依据）。

**分页约定**：列表类 `?limit=50&offset=0` → `{"items": [...], "total": 123, "limit": 50, "offset": 0}`；文件树用游标 `?cursor=<opaque>&limit=200` → `{"items": [...], "next_cursor": "…" | null}`。

**鉴权**：除 E04 与 E01、bootstrap 外全部要求有效 session；写方法（POST/PUT/DELETE）额外要求 Origin 同源（§8）。

**E39 系统时间与时区同步（2026-10-20 交付）**

> 时区从「只读展示」升级为**可手动设置**（下拉选 IANA 时区 → E07 `timezone` 键写入；写入侧前置校验合法 IANA 名——坏值落库会被 `resolve_timezone` 静默回退 UTC，表现为「保存成功但触发时刻没变」，故必须在 E07 钩子拒绝；env 覆盖仍只读 409）。保存后即时 `scheduler.reload()`（调度触发器按新时区重建，「保存即生效不重启」）。

- **`GET /api/system/time`**（`SystemTimeOut`）：服务器 UTC 时刻 + 生效时区（`config.timezone` → `settings.tz`）本地时间与偏移 + `epoch_ms`（前端实时时钟基准，规避本机时钟漂移）+ NTP 探测结果（含 `ntp_servers` **生效链**透传——配置了主备就按配置，未配置回落内置默认链）。探测为 SNTP（RFC 4330）单发单收（纯 asyncio + 标准库，零第三方依赖），候选服务器按序探测，任一成功即用、全失败回最后失败 reason（**DNS 失败也归入 `ntp.unreachable`，禁止裸抛 `gaierror` 500**），结果 **30s 进程内缓存**（缓存键含服务器组——改主备立即换链；前端轮询不得把公网 NTP 池当心跳打）。
- **`POST /api/system/time/sync`**（`TimeSyncOut`）：按 NTP 结果校准系统时钟。只走 libc `clock_settime(CLOCK_REALTIME)`，**不经 shell**（S9 延续）；边界：偏移 < 1s 不动时钟（`clock.noop`）、> 1 天拒绝（`clock.out_of_range`，坏响应防护）、Windows 无对应 POSIX 调用（`clock.unsupported_platform`）、容器缺 `CAP_SYS_TIME`（`clock.permission_denied`）——**一律显式回 reason 机器码，绝不假报成功**，由 UI 转译并指路「宿主机 chrony / systemd-timesyncd 或 `--cap-add SYS_TIME`」。危险动作入审计 `time.sync`（detail 只含 applied/offset/server/reason，零凭据面 S3）。落点 `routers/system.py` + `services/time_sync.py`。
- **通知设置页（R-018 A 方案重构）**：渠道类型下拉（Healthchecks / Webhook / MeoW / SMTP）→ 仅渲染该类型配置项 → 「已保存的渠道」列表（状态 pill + 脱敏摘要 + 编辑/清除，清除走确认门）；全局告警规则（`on_success` / `skipped_threshold`）独立成卡。**零后端改动**（E23 三态写入契约不变：敏感 URL 只回 `*_set` 不回明文）。多实例（同类型多条）留待后续 P 级改造（新表 + 幂等迁移 + Notifier 遍历）。
- **NTP 主备服务器（E39 增补，2026-10-20）**：`ntp_primary` / `ntp_backup` 两个 E07 配置键（主机名或 `主机名:端口`，**空串 = 清除回落内置默认链**；校验器拒空白串/带协议地址/端口越界/超长主机名）。探测与同步按「主 → 备 → 内置链」取值，卡片内展示**生效链**与两个输入框（同批双键保存）。env 覆盖时只读并指路改环境变量（与 timezone 同口径）。

**E44 `POST /api/repos/{repo_id}/password`**（200）：首次写入仓库密码文件 `<PASSFILE_ROOT>/<repo_id>/password`（`RepoPasswordRequest`：`password?`）。

- `password` 为空 → 后端按 `REPO_PASSWORD_LENGTH`（**32 位**，四类字符各至少一个再洗牌，`secrets.SystemRandom`）生成强随机密码，响应 `generated=true` 并**一次性回显明文**（前端以 `SecretReveal` 统一呈现）；非空 → 按用户自填写入，**响应不回显**（`password: null`）。回显口径援 §8 首启随机密码先例：明文不落库、不落日志、不进审计。
- **仅在文件不存在时允许**：该密码既是 restic 仓库密钥，也是 R-025 凭据加密的密钥源（HKDF info 混入 `repo_id`，§4.7）——覆盖会让仓库不可读、已加密凭据全部失效，故已存在 → **422 `VALIDATION_ERROR`**（message 带容器路径，指引到宿主机挂载点手动处理）。
- 写入为原子操作（同目录临时文件 + `os.replace`）并 `chmod 0600`；只读挂载/权限不足 → **422** 且给出可操作提示，**不静默、不 500**。写后调用 `invalidate_repo_status_cache()` 让状态卡即时翻转。
- 审计 `repo.password_set`（`AUDIT_REPO_PASSWORD_SET`）只记 `{generated: bool}`，**明文永不入审计**（红线 S3）。

**`POST /api/repos/{repo_id}/rebuild`**（200）：重建仓库——清空该仓库全部快照、用新密码重新初始化（`RepoPasswordResponse`；`password?` 缺省生成并一次性回显）。**2026-10-21 起对全部仓库开放**（原 default 专属）：删除仓库不触碰磁盘数据，同址新建会撞上打不开的旧仓库（报「密码错误」），非默认仓库此前唯一的指引「删除后换 URL 新建」同址即死循环、无恢复路径。约束：仅本地 FS 后端（远程 422，提示手动清空后端存储后删除重建）；运行中作业 409；写新密码文件 → 清空仓库目录**内容**、保留目录本身（文件系统根硬拒绝）→ `restic init`；仓库密码是凭据加密密钥源（HKDF info 混入 `repo_id`）——重建后旧 enc:v2 凭据无法解密，一并清除（需重新录入）。审计 `repo.rebuild`（`AUDIT_REPO_REBUILD`，detail 只记 `{generated, cleared_credentials}`，明文不入审计，S3）。UI 保留三门确认门（关键词 REBUILD）。**v1.9**：`restic init` 成功后立即调用 `repo_keys.neutralize_repo_key()` 把 `keys/<id>` 里的明文身份（`username`/`hostname`）换成中性值 `svc-backup@repo`（与作业类型 `init` 同一套逻辑；失败只记日志、不反转 init 结果）。

**URL 严格校验（Q20）**（`routers/repos.py`，仅写入路径 POST/PUT；env 同步不走此门）：`s3:`/`b2:`/本地路径**不校验**（零回归）；sftp 双形态 + 拒密码内嵌（走了也是静默误解）；azure/gs 冒号形态 + 容器/桶名规则；rest 协议/主机校验 + **拒 user:pass@ 内嵌**（指向加密凭据字段）；rclone 语法 + **remote 必须在 `listremotes` 清单内**（不在册 422 并列出可用远端；探测不可用时放行、交由 E43 连通性测试终判）。坏 URL 不落库。

**E46 `POST /api/snapshots/tag`**（A3）：快照版本标签（`restic tag --add/--remove`）。请求 `{snapshot_ids?: []，add?: []，remove?: []，tag_filter?: []，host?}` → `restic tag --add/--remove [snapshotIDs]`，解析 `changed`/`summary` JSON 行 → `{changed_count, changed[{old_snapshot_id,new_snapshot_id}], truncated}`。restic `cmd_tag.go` 源码核验的两道约束前移为服务端校验：(1) `add`/`remove` 皆空 → 422（restic 端 "nothing to do!"）；(2) 无 `snapshot_ids` 且无 `tag_filter`/`host` → 422（restic 无 id 即改**全部**匹配快照，高危）。`tag` 动词取独占锁（与备份并发会 exit 11 锁冲突，由 `failure_reason` 明示「仓库锁残留」）。审计动作 `tag.update`（constants.py `AUDIT_TAG_UPDATE`）。实现锚点：`routers/snapshots.py` + `services/restic.py`（`VERBS`/`WhitelistArgs.tag_add/tag_remove`/`_verb_flags` tag 分支）+ `ResticCmd.run_json` 同步执行（非 job，援 forget 预览同步先例）。

**E47 `GET /api/repos/{repo_id}/keys`**（v1.9，**只读**）：仓库密钥身份可见性——`restic key list --json` → `RepoKeysOut`：

```
{ "repo_id": "...", "overall": "neutralized|exposing|mixed|unknown",
  "keys": [ { "id": "70b65d8e", "id_full": "<64 hex>", "user": "svc-backup",
              "host": "repo", "created": "2026-10-23 15:00:51",
              "created_tz": "UTC", "current": true, "neutral": true } ],
  "probe_error": null }
```

- **为什么需要**：`keys/<id>` 是仓库里唯一**明文**文件，`username`/`hostname` 随对象存储对云商可见。端点让用户确认「init 后的中性化是否真生效」「有没有历史遗留的真实身份 key」，不必进容器跑 CLI。威胁模型与加固分层见《云端仓库安全基线.md》§1–§3。
- **`overall` 四态**（`repo_keys.classify_keys` 纯函数）：`neutralized` 全部 key 均中性；`exposing` 存在非中性 key 且无中性 key；`mixed` 两种并存（中性化只处理**唯一** key，多 key 属人工介入场景）；`unknown` 探不到 key（未初始化/仓库不可达，此时 `probe_error` 说明原因）。
- **字段白名单**：只回 `id`（8 位短 id，与 `key list` 表格列一致）/`id_full`（64 hex，供复制到 CLI 排障）/`user`/`host`/`created`/`created_tz`/`current`/`neutral`。**`data`（master key 密文）与 KDF 参数 `salt/N/r/p` 绝不进 API**——它们不是展示所需，回传等于白送一份仓库指纹。
- **`created_tz`**：restic 按子进程 `TZ`（`build_env` 注入 `settings.tz`，默认 `UTC`）渲染 `created` 且**不带时区标记**。服务端补标注、**不做时区换算**（C8 单一时间语义；真机实证：本机 22:45 建库、接口回 `15:00:51`）。
- **无缓存**：不复用 E42 的 30s TTL（容量/stats 代价高才需要缓存），`key list` 是轻量实时探测，且「是否已中性化」是安全判定——吃缓存会给出过期结论。
- **失败不 5xx**：仓库不存在 → 404 `REPO_NOT_FOUND`；地址未配置/口令文件缺失/仓库锁导致探测失败 → **200 + `keys: []` + `probe_error`**（与 E43 口径一致：失败可见，不留空白）。
- **无审计**：只读探测，援 E45 先例。`id` 不属机密（它本来就是 `keys/` 文件名，能读存储的人本就看得到）。

**E48 `GET /api/rclone/configs`**（v1.10，**只读**）：rclone conf 全段清单——`rclone config dump`（JSON）→ `RcloneConfigsOut`：

```
{ "conf_path": "/etc/rclone/rclone.conf", "conf_present": true,
  "configs": [ { "remote": "mycrypt", "type": "crypt", "managed": true,
                 "params": { "remote": "mywebdav:bucket", "filename_encoding": "base64" },
                 "has_credentials": { "password": true, "password2": false } },
               { "remote": "gdrive", "type": "drive", "managed": false,
                 "params": {}, "has_credentials": {} } ],
  "available": true, "reason": null }
```

- **凭据零回显（S3 硬约束）**：`dump` 输出的 `password`/`password2`/`pass`/`bearer_token` 一律替换为 `has_credentials` 布尔，密文永不出后端。
- **`managed` 语义 = 可字段级编辑**：`type` 在注册表（一期 `crypt`/`webdav`）内才 `true`，并回显非凭据参数（`display_keys`）；其余段（OAuth 网盘、宿主机手工配置的 s3/sftp）只有名字与 type，参数恒空。
- **`available=false`**：rclone 二进制缺失/超时/conf 不可读 → 200 + 空列表 + 可操作 `reason`（不 500、不静默，援 E45 口径）。
- **无审计**：只读探测，援 E45 先例。

**E49 `POST /api/rclone/config/{remote_name}`**（v1.10）：新增 conf 段（裁决 1/3/7）。

- 请求 `RcloneConfigWriteRequest`：`{ type, params: Record<string,string>, store_form?: 'obscured'|'plain', value_obscured?: bool, declare_form?: bool|null }`（裁决 16 存储形态两轴）：`store_form` = **目标存储形态**（混淆 / 明文，新建与编辑同一语义；混淆→rclone 混淆一次后落盘，明文→原样落盘），`value_obscured` = 提交的值本身已是混淆产物（与 `store_form='plain'` 矛盾 → 422），`declare_form` = 对形态未知的已存凭据一次性声明形态（只写记录、不改密码）。`params` 只接受注册表内已知键（白名单，未知键 422）。
- 写入路径 = **官方 CLI** `rclone --config <conf> config create <name> <type> k=v...`（裁决 7：不自研 INI 手术；官方自带临时文件 + 双 rename 原子替换 + 备份 + 权限镜像）。
- 响应 `RcloneConfigWriteOut`：`{ remote, type, conf_path, action, remotes_after[] }`——**零凭据**。
- 状态语义：重名 **409**（编排层 dump 预检；rclone 自身重名 exit 0 静默覆盖，不可依赖）/ 未注册类型·OAuth 类型 **422** / 底层远端不在册 **422** / rclone 不可用或写入未落地 **503**。
- 审计 `rclone.config_append`（detail 只含 remote 名与 type）。

**E50 `PUT /api/rclone/config/{remote_name}`**（v1.10）：编辑 conf 段（裁决 9：**仅注册表类型**可编辑，字段级表单，无自由改键口）。

- 语义：**凭据字段留空 = 保持不变**（前端不预填密码）；非凭据键按提交值覆盖。
- 段不存在 → **404**；类型不在注册表（OAuth 网盘/s3/sftp）→ **422**（编辑 OAuth token 无意义：真实恢复必须跑 `rclone authorize` 授权流）。
- 审计 `rclone.config_edit`（detail 含 remote、type 与 `credentials_changed` 布尔，不含凭据）。

**E51 `DELETE /api/rclone/config/{remote_name}`**（v1.10）：删除 conf 段（裁决 8：**全段可删**，含 OAuth 网盘与宿主机手工配置）。

- 段不存在 → **404**（rclone delete 不存在段 exit 0 静默，故预检必需）。
- 风险控制从「API 硬拒绝」改为「**确认门分级 + 审计留痕**」：OAuth 段前端加重提示「删除后需在宿主机重新授权才能再用」，审计 detail 记 `type`。
- 审计 `rclone.config_delete`。

> **写后复核（v1.10，真机实证驱动的护栏）**：单文件 bind mount 下 rclone 写 conf **退出码 0 但无落盘、且写操作挂住不返回**（WSL 真机 A/B 实证见《rclone配置生成工具设计方案.md》§12）。因此三个写端点在 CLI 返回后再 `dump` 复核（新增/编辑比对落值、删除确认段已消失），不符即 **503** 并给出目录挂载指引——禁止把「退出码 0」当成功。所有写操作串行化（单 `asyncio.Lock`，应用为单进程 asyncio）。

> **`repo_id` 命名规则（安全约束，S2/S3 精神）**：`repo_id` 会被拼进密码文件路径，故恒受 `REPO_ID_PATTERN = ^[A-Za-z0-9][A-Za-z0-9_-]*$` 约束（长度 ≤64，**不含 `.` 与 `/`**，从源头排除 `..` 与子目录写法）。校验在两侧生效：建仓 `RepoCreateRequest.id`（schema `Field(pattern=...)`）+ 路径参数侧 `_validate_repo_id()`（非法即 422）。**新增任何拼接 `repo_id` 的端点都必须复用该规则**——漏校验即路径穿越（只读探测会升级为任意文件写入）。

**E36 `POST /api/repos/{repo_id}/backup-tasks/{id}/dry-run`**（200 `DryRunResponse`）：任务域扫描预览（R-026-08）。请求体字段均可选（缺省取任务存量 sources/excludes，支撑「源集合变更后重新预览」）→ `restic backup --dry-run --json --verbose`（与 E31 同链路：120s 超时、5000 条上限、伪文件系统目录名黄色 warnings、restic 非 0 回 200 + `error` 字段）。**预览成功（无 error 且未 truncated）即清 `dry_run_pending=0`**（截断视为未看全，保守不清）。

**E36b `POST /api/repos/{repo_id}/backup-tasks/{id}/export`**（P2，2026-10-22）：**单任务配置导出**——请求 `{password}`（≥10 位，与 E-batch 导出同口令校验）→ 响应 `application/json` 附件（`Content-Disposition: attachment`），包体 `format=restic-web-config-export`、`version=1`、**`kind=backup-task`**。内容仅含该任务 + 其所属仓与镜像仓（`notify`/`behavior` 等全局设置**不带**）、凭据只带相关仓的 `cred.{repo_id}.*` 且走口令加密段（S3：响应无明文）。审计 `config.export`（target=`task:{id}`，detail 只含任务名与计数）。导入侧按 `kind` 分流（方案 §4.5.9 R-5）：单任务包**不写全局 notify/behavior**，且即使 `replace_existing=true` 也**不覆盖** 同仓同名任务。


> E31（`POST /api/sources/dry-run`）契约不变，定位收窄为「向导内**无任务实体**的新建流预览」（sources 必填）；任务实体存在后用 E36。E05 仍是无状态目录浏览——「源选择 per-task」指选择态存入 `backup_tasks.sources`，非 E05 契约变更。

```mermaid
        JR-->>SC: JobConflictError
        SC->>DB: INSERT jobs(status=cancelled, trigger=scheduled, summary='与运行中任务冲突，本次调度跳过')

        Note over SC: 不重试排队；下个 cron 周期自然再试
    else 空闲

        JR-->>SC: success/failed
    end
    Note over JR: prune 到期（prune_interval_days）由 SchedulerService 独立判到期 → **仅置卡片 prune_due 提示**
    Note over JR: N3 裁决（2026-10-14）：自动 forget 已开放——backup 成功回调 → maybe_auto_forget（到期 + keep 规则非空护栏），结果经 R-018 Notifier 事后告知；手动裁剪走 R-016 预览-确认流（三重确认门）
```

> **每日校验改 n/t 确定性分桶（2026-10-21 策略收口）**：`--read-data-subset` 的 `x%` 形态在 restic 中是**随机**子集——官方文档明示「will not guarantee to cover all available pack files after sufficient runs」（按 2%/天计，30 天累计覆盖率仅 ≈45.5%，且大量重复读）。改为 **`n/t` 确定性分桶**：`t = behavior.check_subset_denominator`（全量扫描周期天数，缺省 30），当天桶号 `n = (本地日期序数 % t) + 1`，**t 天恰好把全仓数据块无重复、无遗漏读一遍**（实测 restic 0.18.0：16 packs / t=8 时输出 `read group #N of X data packs ... in 8 groups`，各组 2/2/1/5/3/1/2/0 = 16）。分桶按 pack ID 哈希、同一 pack 恒定落同桶，故新写入的 pack 会在下一轮被覆盖到。`t=0` = 不做每日扫描。
>
> **月度全量重定位**：新增独立开关 `behavior.monthly_full_enabled`（**缺省关**）——每日 n/t 已按周期覆盖全量，月度全量仅在需要「某一时刻的完整校验结论」时手动打开（代价是多读一遍全量）。打开时，**全量当天跳过每日抽样**（04:00 全量已读遍，04:30 的抽样属纯重复读）。

**关键语义**：① 时区 = `config.timezone` → `settings.tz` → UTC（cron 解释与「当天」判定同源）；② jitter = `config.schedule.jitter`（缺省 300s，上限 3600s），在 fire 回调内 sleep，顺序为「查 enabled → jitter → 记账 → submit」（先记账后执行防崩溃重复触发）；③ 冲突不排队——scheduled 提交遇活跃 job 落 cancelled + `job.skipped_conflict`，下个周期自然再试（E1）。

### 7.10 子进程事件循环约束（2026-10-20 新增，Windows 实证）

restic 与 rclone 全部经 `asyncio.create_subprocess_exec` 拉起。该 API 在 `SelectorEventLoop` 上**未实现**（`asyncio/base_events.py:539` 抛 `NotImplementedError`），而 uvicorn 的 `--reload` / `--workers > 1` 在 Windows 会用 `use_subprocess=True` 并强制选用 `SelectorEventLoop`——结果是**所有 restic/rclone 操作 500**（真机实证：rclone 探测报「服务器内部错误」，易误判为二进制缺失）。

**四层防护（已落地）**：

| 层 | 位置 | 行为 |
|---|---|---|
| 1 | `constants.SUBPROCESS_LOOP_HINT` | 统一错误文案，直指修法（`--loop none`；`dev-scripts/dev.ps1` 已内置） |
| 2 | `services/rclone.py:list_remotes` | 捕 `NotImplementedError` → 降级 `available=False` + 可操作 `reason`（与缺二进制/超时同口径，**绝不裸 500**） |
| 3 | `services/restic.py:spawn` | 捕同异常 → `ResticFailedError(SUBPROCESS_LOOP_HINT)`，不再抛出未捕获异常 |
| 4 | `main.py` lifespan 启动自检 | `win32` 且当前循环非 `ProactorEventLoop` → `logger.error` 明示（避免用户到第一次备份才发现） |

**启动纪律**：Windows 本机起后端**必须 `--loop none`**（`dev-scripts/dev.ps1 restart backend` / `uvicorn app.main:app --reload --loop none --port 8000`）；Linux 与容器内无此问题（默认 Proactor/uvloop 均支持子进程）。护栏：`backend/tests/test_subprocess_loop_guard.py`（2 例：降级不抛 + 提示文案正确）。

> 排障判别：本机**未安装** restic/rclone 时，探测会诚实返回 `available=False` + `reason`（预期降级，非缺陷）；只有「异常冒泡为 500」才是事件循环问题。

- **Server State（@tanstack/vue-query）**：全部 REST 请求；失效策略——任务终态事件后 invalidate `jobs`/`snapshots`/`backup-tasks`（TanStack Query 官方 Vue 适配版，失效策略不变）；
- **UI State（Pinia，克制）**：会话态（me 缓存）、暗色主题、全局 message（`useUiStore` defineStore）；**不缓存任何服务端数据**；
- **SSE 不进 Vue 响应式树**：`useJobStream(jobId)` composable 内部持有 EventSource，暴露 `progress/log/done/error` 回调与 `lastEventId`；组件卸载即 close，重挂载自动凭 Last-Event-ID 续传（对应 PRD US-D1 AC1 刷新不丢进度）。

### 9.3 SSE 客户端封装要点

```typescript
// composables/useJobStream.ts
// 1. new EventSource(`/api/jobs/${id}/stream`) —— cookie 自动携带，无自定义 header
// 2. 浏览器重连自动带 Last-Event-ID；首次订阅如已知进度偏移可经 ?last_event_id= 传入
// 3. 心跳超时检测：>45s 无任何行（含 : keep-alive）判定断链 → 显式 close + query 重取状态
// 4. done/error 事件后 close，并 invalidateJobs()
```
