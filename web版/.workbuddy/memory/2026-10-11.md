## 解决"两个环境限制"——两个都能解决，且发现更严重的问题

### 1. 后端 pytest 并非"环境不可靠"（上一轮结论错误，已撤销）
- 实测：清理残留 python 进程后，**全量连跑 3 轮均 117 passed**（约 35s/轮）；单跑 state_machine / test_migrations 用例秒过。
- 真实原因：本会话内几条超时被杀、未回收的 python 进程叠加，与 ProactorLoop / aiosqlite 无关。
- **教训**：遇到"必现挂起"先查残留进程（`tasklist | findstr python`）再下架构结论；我曾用 stash 对照+faulthandler 强行归因到 ProactorLoop，是**误判**。

### 2. .dockerignore 上轮其实有真实缺陷（本轮用真实语义校验才抓到）
- 上轮用 fnmatch 模拟校验 → **漏判**。本轮写 `scripts/check_dockerignore.py`（真实 dockerignore 匹配语义）后抓出 3 个缺陷：
  `**/.env` 只覆盖带层级路径，**上下文根的 .env 不被匹配**（凭据可能进镜像）；`.git/`、`.workbuddy/` 同问题（其中 .workbuddy/ 真实存在于 web版/）。
- 工具自身 bug：`path.lstrip("./")` 按**字符集**剥离，把 `.env`/`.workbuddy` 的前导点一起吃掉 → 规则永远匹配不到。改为只剥 `./` 与 `/` 前缀。
- 已接入 verify_redlines.sh（第 16 项）；反向注入验证双向都能报红。

### 3. ⚠️ 发现真实高危漏洞：starlette 0.48.0 有 12 个 CVE
- 本机无 docker/trivy → 改用 **pip-audit + OSV 后端**（pypi.org 直连超时，OSV 可达），从 uv.lock 导出清单扫描。
- 命中：PYSEC-2026-1942(Range DoS,需≥0.49.1) / -161(Host头投毒,≥1.0.1) / -2280(HTTPEndpoint,≥1.1.0) / -2281(StaticFiles SSRF+NTLM,≥1.1.0) / -248(authority污染,≥1.3.0) / -249(urlencoded限额失效,≥1.3.1)。
- **影响面已核实**：项目**未使用** StaticFiles/FileResponse/request.form/HTTPEndpoint，且单容器自部署无反代 Host 注入面 → 实际可利用性低。
- **升级阻塞（关键）**：`fastapi<0.120` 传递要求 `starlette<0.49.0`，与修复版本冲突；实测 `starlette>=1.3.1` 与 `>=0.49.1,<1` 均**无法解**。需放宽 fastapi 上限（最新稳定 0.143.0）后全量回归——**属跨大版本升级，未擅自做，已回退 pyproject.toml 并把事实写入规范**。
- pip-audit 参数坑：`--locked` 需配项目路径但不支持 uv.lock；正确做法是 `uv export --format requirements-txt`（注意 `-f requirements.txt` 会被误解析为 find-links，须用全名）后 `-r` + `-s osv`。
